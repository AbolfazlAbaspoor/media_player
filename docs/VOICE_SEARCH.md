# جستجوی صوتی (Voice Search)

با دستورِ `vs` حرف بزن، ربات صداتو ضبط می‌کنه، به متن تبدیلش می‌کنه، و
دقیقاً همون کاری رو می‌کنه که `p <متن>` می‌کرد -- یعنی همون سرویس/موتورِ
جستجویی که همیشه استفاده می‌کنی. منطق اصلی توی `core/voice_search.py`،
موتورهای تبدیلِ گفتار به متن توی `core/stt.py`، و دستورهاش `vs`/`vss`
(توی `commands/`).

## این چیه، چی نیست

  * **هست**: یه راهِ جایگزین برای تایپ‌کردنِ سرچ -- صداتو می‌گیره، متن
    می‌کنه، و همون مسیرِ همیشگیِ `p` رو صدا می‌زنه.
  * **نیست**: یه دستیارِ صوتیِ عمومی یا یه سیستمِ ضبطِ مکالمه. ربات فقط
    وقتی صدای یه نفر رو می‌گیره که همون لحظه `vs` زده باشه، فقط چند ثانیه،
    و فقط از همون یه نفر.

## چطور کار می‌کنه

1. `vs` بزن (یا `vs <زبان>` برای یه‌بار مصرف با زبونِ دیگه، مثلاً `vs en`).
2. ربات فقط صدای *تو* رو subscribe می‌کنه (نه کسِ دیگه‌ای توی کانال) و منتظر می‌مونه شروع کنی به حرف زدن (`start_timeout_seconds`).
3. تا وقتی حرف می‌زنی صدات جمع می‌شه؛ چند لحظه بعد از سکوت (`silence_seconds`) یا رسیدن به سقفِ `max_seconds`، ضبط تموم می‌شه.
4. اشتراکِ صدات و رویدادِ صداش بلافاصله قطع می‌شه -- چه موفق بشه چه نه، چه لغو کنی، چه قطع بشی.
5. اگه ضبط خیلی کوتاه بود (`min_seconds`) دور ریخته می‌شه.
6. صدا به گفتار تبدیل می‌شه (موتورِ تنظیم‌شده) و یه خط بهت می‌گه چی شنیده («Heard: ...»).
7. همون متن دقیقاً مثلِ این‌که `p <متن>` زده باشی جستجو و پخش می‌شه.

`vs cancel` هر جستجوی صوتیِ درحال‌اجرا رو (هرکی شروعش کرده) متوقف می‌کنه.
هر لحظه فقط یه جستجوی صوتی می‌تونه در جریان باشه؛ نفرِ دومی که `vs` بزنه
پیامِ «مشغوله» می‌گیره.

### وقتی توی کانالِ ربات نیستی

ربات به‌طور پیش‌فرض فقط صدایی رو می‌گیره که از *کانالِ خودش* بیاد (طبقِ
پروتکل تیم‌تاک). اگه توی کانالِ ربات نباشی و `vs` بزنی:

  * اگه `intercept` روشن باشه (پیش‌فرض) **و** خودِ ربات با یه حسابِ نوع
    ادمین لاگین کرده باشه، صدات از هر کانالی که باشی گرفته می‌شه
    (`SUBSCRIBE_INTERCEPT_VOICE` -- سرور فقط به حسابِ ادمین اجازه‌ی
    intercept می‌ده).
  * وگرنه یه پیامِ روشن می‌گیری که باید بیای توی کانالش.

## موتورها و مصالحه‌هاشون

اضافه‌کردنِ یه موتورِ جدید یعنی *یه کلاس* توی `core/stt.py` با
`@register`؛ بقیه‌ی زنجیره (ضبط، تبدیلِ فرمت، پیام‌ها، جستجو) دست نمی‌خوره.

  * **google** (پیش‌فرض) -- همون endpoint رایگانِ Google Web Speech که
    کتابخونه‌ی معروفِ SpeechRecognition هم استفاده می‌کنه. بدونِ ثبت‌نام و
    بدونِ کلیدِ اختصاصی کار می‌کنه (یه کلیدِ عمومی توی خودِ کد هست)، هر
    زبونی که گوگل بشناسه (`fa-IR`، `en-US`، `ar-SA`، ...). **مصالحه**:
    تشخیصِ خودکارِ زبان نداره (باید زبون رو دقیق بدی)، رایگان ولی
    غیررسمی/بدون SLA، و چون endpoint گوگله، جاهایی که به گوگل دسترسِ
    مستقیم ندارن (مثلاً ایران) به پروکسیِ خودِ ربات نیاز داره.
  * **openai** -- هر سروری که `POST /v1/audio/transcriptions` سازگار با
    OpenAI داره: خودِ OpenAI (مدلِ `whisper-1`)، Groq (سریع‌تر و
    ارزون‌تر، مدلِ `whisper-large-v3`)، یا یه faster-whisper محلی روی
    همون سیستم/شبکه‌ی داخلی. آدرس/کلید/مدل قابلِ‌تنظیمن؛ زبون اختیاریه
    (خالی = تشخیصِ خودکار). **مصالحه**: نیاز به کلیدِ API (و هزینه، مگر
    یه سرورِ محلیِ رایگان بذاری)، ولی کیفیتِ تشخیصِ به‌مراتب بهتر و
    تشخیصِ خودکارِ زبون داره. سرورِ روی همین سیستم/شبکه‌ی داخلی (مثلاً
    `127.0.0.1`) همیشه مستقیم صدا زده می‌شه، نه از پروکسی.

هردو موتور فقط از `urllib` (stdlib) استفاده می‌کنن، پروکسیِ خودِ ربات
(`proxy`) رو رعایت می‌کنن (پروکسیِ socks پشتیبانی نمی‌شه -- به‌جای یه
timeout مبهم، همون اول پیامِ روشن می‌ده)، و هیچ‌وقت کلیدِ API رو توی پیامِ
خطا نشون نمی‌دن.

## محدودیتِ گوگلِ رایگان و کلیدِ شخصی

موتورِ `google` از endpointِ رایگان و *مشترکِ* Web Speech با یه کلیدِ
عمومی استفاده می‌کنه. گوگل وقتی این کلید/IP رو محدود می‌کنه **هیچ خطایی
نمی‌ده و فقط جواب نمی‌ده** (اندازه‌گیریِ زنده: جواب‌های سالم ۱ تا ۳ ثانیه،
بقیه تا آخرِ مهلت ساکت، روی هر دو مسیرِ پروکسی و مستقیم). ربات برای این:

  * هر تلاش حداکثر ۱۰ ثانیه صبر می‌کنه و یک بار (با backoffِ کوتاه، از
    مسیرِ دیگه‌ی پروکسی/مستقیم) دوباره امتحان می‌کنه؛
  * بین دو درخواست حداقل ۱٫۵ ثانیه فاصله می‌ندازه؛
  * اگه هر دو تلاش شکست خورد، ۳۰ ثانیه (با تکرار تا ۵ دقیقه) cooldown
    می‌ذاره و توی اون مدت *فوراً* پیامِ «گوگل موقتاً محدود کرده، N ثانیه
    دیگه» می‌ده، نه ۲۰ ثانیه انتظارِ بی‌نتیجه؛
  * اگه موتورِ `openai` واقعاً تنظیم شده (کلید یا سرورِ محلی)، خودکار
    به‌جای گوگل از اون استفاده می‌کنه.

برای پایداریِ کامل کلیدِ شخصیِ خودت رو بذار:

```
vss google_key <کلیدِ Speech-to-Text/Chromium API خودت>
vss engine openai            (یا موتورِ Whisper/Groq/محلی، با openai_base_url و openai_api_key)
```

## تنظیمات (`vss` یا `shared_config.json` -> `"voice_search"`)

```
vss                     نمایشِ همه‌ی تنظیمات (کلیدهای حساس نیمه‌پنهان)
vss <key> <value>       تغییرِ یه کلید (فقط admin_bot)
```

| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `engine` | `google` | `google` یا `openai` |
| `language` | (خالی) | کدِ BCP-47 (مثلِ `fa-IR`)؛ خالی = زبونِ خودِ ربات (`fa`→`fa-IR`، `en`→`en-US`) |
| `service` | (خالی) | اسمِ یه سرویسِ قابل‌سرچ (مثلِ `youtube`)؛ خالی = همون سرویسِ فعالِ همیشگیِ `p`/`w` |
| `max_seconds` | `10` | سقفِ مدتِ ضبط |
| `start_timeout_seconds` | `8` | چقدر منتظرِ شروعِ حرف‌زدن بمونه |
| `silence_seconds` | `1.0` | بعد از سکوت چقدر صبر کنه قبل از این‌که بگه «حرفت تموم شد» (مکثِ کوتاهِ وسطِ جمله رو قطع نمی‌کنه) |
| `min_seconds` | `0.6` | ضبطِ کوتاه‌تر از این دور ریخته می‌شه |
| `request_timeout_seconds` | `20` | مهلتِ شبکه برای خودِ درخواستِ تشخیصِ گفتار |
| `announce` | `false` | `true` یعنی «چی شنیدم» به‌جای فقط خودِ فرستنده، به کانال هم گفته بشه |
| `intercept` | `true` | اجازه‌ی گرفتنِ صدای کاربرِ خارج از کانالِ ربات (فقط وقتی خودِ ربات ادمین باشه) |
| `openai_base_url` | `https://api.openai.com/v1` | آدرسِ پایه‌ی موتورِ `openai` |
| `openai_api_key` | (خالی) | کلیدِ API (نیمه‌پنهان توی `vss`) |
| `openai_model` | `whisper-1` | مدل (مثلاً `whisper-large-v3` روی Groq) |
| `google_key` | (کلیدِ عمومی) | کلیدِ موتورِ `google`؛ عادی نیازی به تغییر نداره |

کانفیگ‌های قدیمی خودکار همین پیش‌فرض‌ها رو می‌گیرن (همون merge که بقیه‌ی
کلیدهای جدید هم استفاده می‌کنن).

## حریمِ خصوصی

  * صدا **هیچ‌وقت روی دیسک نوشته نمی‌شه**: PCM خام، WAV، و بدنه‌ی
    multipart همه فقط توی حافظه ساخته می‌شن و بعد از پایانِ ضبط (موفق یا
    نه) از حافظه هم می‌رن -- نه یه فایلِ موقت، نه هیچ‌جای دیگه.
  * هیچ لاگی صدای خام یا متنِ تشخیص‌داده‌شده رو ذخیره نمی‌کنه؛ تنها اثرِ
    یه جستجوی صوتی توی لاگ‌ها همون برچسبِ عملیاتِ لحظه‌ای‌ست (مثلاً «در
    حالِ تشخیصِ گفتار برای فلان‌یوزر با موتورِ google») -- دقیقاً هم‌سطحِ
    چیزی که خودِ `p <متن>` هم برای یه سرچِ متنی لاگ می‌کنه.
  * کلیدهای API (`openai_api_key`، `google_key`) توی `vss` نیمه‌پنهانن و
    توی پیامِ خطا هیچ‌وقت کامل چاپ نمی‌شن (`core/stt.py:scrub`).
  * هیچ متنِ خامِ exception (خطای شبکه/HTTP) مستقیم به کاربر نشون داده
    نمی‌شه؛ همیشه از `core/logging_setup.py:safe_error_text` رد می‌شه.

### ایمنیِ پخش

ربات فقط پخش می‌کنه؛ صدای کاربری که `vs` می‌زنه هیچ‌وقت به لاینی که ربات
ازش موزیک پخش می‌کنه نمی‌رسه. تحقیقِ کامل (چرا mute/volume=0 کافی نیست، و
چرا به‌جاش یه دستگاه خروجیِ *مجازیِ* تیم‌تاک باز می‌شه) بالای بخشِ
«جستجوی صوتی» توی `core/teamtalk/ttbot.py` مستند شده؛ خلاصه‌ش:

  * AudioBlock/USERSTATE_VOICE فقط وقتی میان که یه دستگاه خروجیِ تیم‌تاک
    باز باشه -- برای همین یه دستگاهِ مجازی (`TT_SOUNDDEVICE_ID_TEAMTALK_VIRTUAL`)
    باز می‌شه که فقط decode می‌کنه، به هیچ کارتِ صدای واقعی‌ای نمی‌رسه.
  * mute/volume=0 روش نیست: توی این نسخه‌ی SDK بهره‌ی همون mute/volume
    روی خودِ AudioBlock هم اثر می‌ذاره، پس فقط سکوت ضبط می‌شد -- نه صدای
    واقعی.

## لایسنس

`voice_search` یه «قابلیت» است (مثلِ `documentary`/`iptv`)، نه یه
سرویسِ پخشِ عادی. توی `licensing/catalog.py`:

  * `CAPABILITY_SERVICES` شاملِ `"voice_search"` است.
  * امکانِ `cap_voice_search` سرویسِ `voice_search` رو باز می‌کنه و
    دستورهای `vs`/`vss` رو بهش وصل می‌کنه.

دستورهای `vs`/`vss` مثل هر دستورِ دیگه‌ای همیشه وجود دارن؛ اگه لایسنس
`cap_voice_search` رو نداشته باشه، اجراشون می‌گه «توی لایسنست نیست».
برخلافِ `iptv`/`documentary`، جستجوی صوتی مسیرِ جایگزینی (مثلِ «عدد
خام») نداره -- تنها راهِ ورودش خودِ دستورِ `vs` است، که همون دیسپچرِ
`bot.py` قبل از اجراش لایسنس رو چک می‌کنه؛ پس نیازی به چکِ دومِ داخلِ
`core/voice_search.py` نیست.

## محدودیت‌های شناخته‌شده

  * هر لحظه فقط یه جستجوی صوتی توی کل ربات می‌تونه در جریان باشه.
  * موتورِ `google` تشخیصِ خودکارِ زبون نداره -- اگه زبونِ کانفیگ‌شده با
    زبونِ واقعیِ کاربر فرق کنه، نتیجه معمولاً بی‌معنی می‌شه.
  * صدای گرفته‌شده به فرمتِ ۱۶کیلوهرتز/مونو/۱۶بیتی تبدیل می‌شه (stdlib
    خالص -- `audioop` عمداً استفاده نشده چون منسوخ شده)؛ صدای خیلی
    بی‌کیفیت یا با نویزِ زیاد طبیعتاً نتیجه‌ی تشخیصِ ضعیف‌تری می‌ده.
  * `intercept` فقط وقتی واقعاً کار می‌کنه که خودِ ربات یه حسابِ نوع
    ادمین باشه؛ وگرنه تنظیمِ `intercept=true` بی‌اثره و کاربرِ خارج از
    کانال همچنان پیامِ «باید توی کانالم باشی» می‌گیره.
