# اجرا روی Railway

روی Railway فقط **یک سرویس** اجرا می‌شه و فقط یک دستور: `python license_server.py`.
همین یه پروسه همه‌چیز رو بالا می‌آره: ربات فروش تلگرام، سوپروایزر ربات‌های
تیم‌تاک و ربات‌های شخصی مشتری‌ها. داکر (`Dockerfile`) همه‌ی چیزهای لازم رو
خودش نصب می‌کنه و سرور صدا (pulseaudio) رو هم خودش بالا می‌آره.

> سرویس هیچ پورت یا دامنه‌ی عمومی نمی‌خواد. ربات تلگرام با polling کار می‌کنه.

---

## راه سریع: اسکریپت راهنما

```bash
python deploy/railway_setup.py
```

اسکریپت قدم‌های پایین رو به ترتیب انجام می‌ده: گرفتن `libTeamTalk5.so`،
چک فایل‌های بالای ۱۰۰ مگ و فایل‌های محرمانه، commit و push، ساختن فایل
متغیرها، و راهنمای داشبورد Railway. هر جا کار دستی لازم باشه همون‌جا
می‌ایسته، توی کنسول می‌گه چیکار کنی، و با Enter ادامه می‌ده. هر بار که
دوباره اجراش کنی قدم‌های انجام‌شده رد می‌شن.

**کدوم SDK؟** `tt5sdk_v5.22a_ubuntu22_x86_64.7z` (معمولی). اگه سرور
تیم‌تاکت اتصال رمزنگاری‌شده می‌خواد `tt5prosdk_v5.22a_ubuntu22_x86_64.7z`.
بقیه (ios، macos، raspbian) روی Railway به کار نمی‌آن.

---

## قبل از شروع: دو چیز که باید بدونی

**۱. فایل‌های `.dll` و `.exe` ویندوز روی Railway به کار نمی‌آن.**
Railway لینوکس است. `ffmpeg`، `libmpv`، `pulseaudio` و `tesseract` موقع
ساخت ایمیج با `apt` نصب می‌شن. پس فایل‌های سنگین ویندوزی (اون‌هایی که
بالای ۱۰۰ مگ‌ان) **نباید** توی گیت‌هاب باشن. `.gitignore` و `.dockerignore`
الان همه‌ی `*.dll`، `*.exe`، پوشه‌ی `bin/` و `tesseract/` رو کنار می‌ذارن.

**۲. تنها فایل باینری که باید خودت بذاری: `libTeamTalk5.so`.**
SDK تیم‌تاک دانلود خودکار نداره. نسخه‌ی **لینوکس x86_64** رو از
[bearware.dk/teamtalksdk](http://bearware.dk/teamtalksdk) بگیر، از داخلش
`libTeamTalk5.so` رو دربیار (مسیر معمول داخل آرشیو:
`Library/TeamTalk_DLL/libTeamTalk5.so`) و اینجا بذار:

```
core/teamtalk/libTeamTalk5.so
```

حجمش چند ده مگابایت است، پس مشکل ۱۰۰ مگ گیت‌هاب رو نداره. نسخه‌ی SDK رو
هم‌خانواده‌ی `TeamTalk5.py` داخل پروژه بگیر (نسخه‌ی ۵.x). اگه فایل نباشه،
ساخت ایمیج عمداً با پیام خطای واضح متوقف می‌شه.

## قدم ۱: آماده کردن کد

### راه الف: از طریق گیت‌هاب (پیشنهادی)

۱. یک ریپوی **Private** بساز.
۲. توی یه پوشه‌ی **تمیز** پروژه رو بریز (بدون `data/` و بدون فایل‌های `.dll`) و:

```bash
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/<نام‌کاربری>/<نام‌ریپو>.git
git push -u origin main
```

۳. قبل از push، اندازه‌ی فایل‌ها رو چک کن. هیچ‌کدوم نباید بالای ۱۰۰ مگ باشه:

```bash
git ls-files -z | xargs -0 du -k | sort -rn | head
```

اگه قبلاً یه ریپوی قدیمی داشتی که توش `.dll` بزرگ commit شده، گیت‌هاب push
رو رد می‌کنه، حتی اگه الان فایل رو پاک کرده باشی (چون توی تاریخچه می‌مونه).
ساده‌ترین راه: همون کار بالا (`git init` توی پوشه‌ی تمیز) تا تاریخچه‌ی
جدید و بدون فایل سنگین داشته باشی.

### راه ب: بدون گیت‌هاب (از روی کامپیوتر)

Railway CLI رو نصب کن ([docs.railway.com/guides/cli](https://docs.railway.com/guides/cli))،
بعد توی پوشه‌ی پروژه:

```bash
railway login
railway link        # یا railway init برای پروژه‌ی جدید
railway up
```

`railway up` همین پوشه رو آپلود می‌کنه و `.dockerignore` فایل‌های سنگین و
`data/` رو بیرون می‌ذاره.

## قدم ۲: ساخت سرویس

۱. توی [railway.com](https://railway.com): **New Project ← Deploy from GitHub repo**
   و ریپوی خودت رو انتخاب کن. (`railway.json` به Railway می‌گه با `Dockerfile` بسازه.)
۲. اولین deploy بدون متغیر شکست می‌خوره و پیام «توکن تنظیم نشده» می‌ده.
   طبیعیه؛ قدم‌های بعد رو انجام بده.

## قدم ۳: Volume (برای نگه‌داشتن دیتا)

بدون Volume، دیتابیس لایسنس‌ها، ربات‌های مشتری‌ها و تنظیمات با **هر
deploy پاک می‌شه**.

سرویس رو باز کن ← **Settings** (یا کلیک راست روی سرویس ← **Attach Volume**)
← یه Volume بساز و **Mount Path** رو دقیقاً این بذار:

```
/app/data
```

## قدم ۴: متغیرها (Variables)

توی تب **Variables** سرویس:

| متغیر | لازم؟ | مقدار |
|---|---|---|
| `LICENSING_BOT_TOKEN` | بله | توکن ربات از BotFather |
| `LICENSING_ADMIN_IDS` | بله | آیدی عددی تلگرامت (چند مدیر: با ویرگول جدا کن، مثلاً `111,222`) |
| `LICENSING_CARD_NUMBER` | بله* | شماره کارت. *اگه فقط پرداخت کریپتو داری لازم نیست |
| `LICENSING_CARD_HOLDER` | نه | نام صاحب کارت |
| `LICENSING_CARD_BANK` | نه | نام بانک |
| `LICENSING_SUPPORT_USERNAME` | نه | یوزرنیم پشتیبانی |
| `LICENSING_CRYPTO_ADDRESS` | نه | آدرس کیف پول (پرداخت تتر) |
| `LICENSING_TRONGRID_API_KEY` / `LICENSING_EXPLORER_API_KEY` | نه | کلیدهای API پرداخت تتر |
| `CF_ACCOUNT_ID` / `CF_KV_NAMESPACE` / `CF_API_TOKEN` | نه | Cloudflare (لایسنس اجاره‌ای) |
| `LICENSING_PROXY_URL` | نه | روی Railway معمولاً لازم نیست؛ تلگرام اونجا فیلتر نیست |

آیدی عددی و توکنی که الان توی `data/licensing/config.json` خودت داری رو
همین‌جا وارد کن (فایل `data/` عمداً توی ریپو نیست).

> **امنیت:** توکنی که توی بکاپ‌های قبلی بوده رو از BotFather با `/revoke`
> عوض کن و توکن جدید رو همین‌جا بذار. توکن و کلید خصوصی هیچ‌وقت نباید توی
> ریپو یا زیپی که برای کسی می‌فرستی باشه.

بعد از ذخیره‌ی متغیرها، سرویس خودش دوباره deploy می‌شه.

## قدم ۵: چک کردن

توی تب **Deployments ← View Logs** باید این‌ها رو ببینی:

```
محیط اجرا: ...
سوپروایزر ربات‌ها: فعال
ربات‌های شخصی مشتری‌ها: فعال
ربات فروش در حال اجراست.
```

بعد توی تلگرام به ربات `/start` بزن (با حساب مدیر).

## چیزی که کجا نگه‌داری می‌شه

| چی | کجا |
|---|---|
| دیتابیس لایسنس، تنظیمات، قیمت‌های سفارشی، رسیدها، کلیدها | Volume (`/app/data/licensing/`) |
| ربات‌های مشتری‌ها (کانفیگ، تاریخچه) | Volume (`/app/data/<سرور>_<پورت>/...`) |
| لاگ‌ها | تب Logs در Railway (و `/app/errors/`، که با deploy پاک می‌شه) |

## انتقال دیتای قبلی (اختیاری)

اگه می‌خوای لایسنس‌ها و کلید قبلیت (`data/licensing/`) سر جاش بمونن، باید اون
فایل‌ها رو یک بار روی Volume کپی کنی. اگه اون دیتا فقط تست بوده، همون بهتره
از صفر شروع کنی: `license_server.py --init` همه‌چیز رو خودکار می‌سازه. اگه
نیاز شد، بگو تا قدم‌به‌قدم کمکت کنم.

## محدودیت‌ها و نکته‌ها

- **منابع:** هر ربات پخش صدا حدود ۱۰۰ مگابایت رم می‌خواد و ترافیک شبکه
  مصرف می‌کنه (`docs/SERVER.md`). پلن Railway رو بر اساس تعداد ربات‌ها انتخاب کن.
- **Volume فقط به یک سرویس وصل می‌شه** و سرویس رو نباید با بیش از یک
  replica اجرا کنی (دو ربات تلگرام با یک توکن به هم می‌ریزن).
- **ویدیوهایی که نیاز به مرورگر دارن:** پکیج `playwright` نصبه ولی مرورگرش
  (Chromium) توی ایمیج نیست تا حجم کم بمونه. فقط استخراج لینک از چند سایت
  خاص رو تحت تأثیر می‌ذاره؛ بقیه‌ی امکانات کار می‌کنن.
- **تنظیمات `crypto.enabled` و `crypto.network`** فقط توی فایل کانفیگ هستن،
  نه متغیر محیطی. اگه پرداخت تتر می‌خوای، بگو تا برایش راه تنظیم از روی
  Railway اضافه کنیم.

## عیب‌یابی

| پیام | علت و راه حل |
|---|---|
| ساخت ایمیج: `libTeamTalk5.so is missing` | فایل رو توی `core/teamtalk/` بذار و دوباره commit/push کن |
| ساخت ایمیج: `needs the libraries listed above` | SDK با بیلد لینوکسِ دیگه‌ای ساخته شده؛ نسخه‌ی x86_64 مناسب Ubuntu 22 رو بگیر |
| `The sales bot token is not set` | `LICENSING_BOT_TOKEN` یا `LICENSING_ADMIN_IDS` رو توی Variables بذار |
| `No card number is configured` | `LICENSING_CARD_NUMBER` رو بذار (یا پرداخت کریپتو رو فعال کن) |
| دیتا بعد از deploy پاک شد | Volume با Mount Path `/app/data` وصل نیست |
| `pulseaudio is not answering` | اگه لاین صدا نمی‌سازه لاگ کامل رو بفرست |
| `Conflict: terminated by other getUpdates request` | یه نسخه‌ی دیگه (روی کامپیوتر خودت) هنوز با همین توکن اجرا می‌شه؛ خاموشش کن |
