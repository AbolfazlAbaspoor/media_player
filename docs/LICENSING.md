# پلتفرم لایسنس و فروش

یه ربات تلگرام که ربات پخش تیم‌تاک رو می‌فروشه، لایسنس صادر می‌کنه، برای
هر مشتری لاین صدا می‌سازه، و ربات‌ها رو روی سرور اجرا و نگه می‌داره.

---

## راه‌اندازی سریع

```bash
pip install -r requirements-license.txt
python license_server.py --init     # فایل‌های کانفیگ نمونه + کلید امضا
```

بعد `data/licensing/config.json` رو پر کن:

```json
{
  "sales_bot_token": "123456:AA...",
  "admin_ids": [123456789],
  "card_number": "6037991234567890",
  "card_holder": "نام صاحب کارت",
  "card_bank": "ملی"
}
```

آیدی عددی تلگرامت رو با @userinfobot پیدا کن. توکن‌ها رو می‌تونی با متغیر
محیطی هم بدی (امن‌تر روی سرور):

```bash
export LICENSING_BOT_TOKEN=123456:AA...
export LICENSING_ADMIN_IDS=123456789
```

```bash
python license_server.py --check    # بررسی آمادگی
python license_server.py            # اجرا
```

`--check` واقعاً یه `getMe` به تلگرام می‌زنه، پس اگه سرور به
api.telegram.org نمی‌رسه همون‌جا معلوم می‌شه، نه بعد از راه‌اندازی.

### پروکسی (جایی که تلگرام فیلتره)

```json
{
  "proxy_url": "socks5://127.0.0.1:1080",
  "telegram_poll_timeout": 10,
  "telegram_timeout": 30
}
```

یا `export LICENSING_PROXY_URL=socks5://127.0.0.1:1080`.

نکته‌ها:

  * خالی‌گذاشتن `proxy_url` یعنی «هرچی محیط می‌گه»: `HTTPS_PROXY` و روی
    ویندوز پروکسی سیستم. روی سرور لینوکسی پروکسی سیستمی وجود نداره، پس
    اونجا این کلید تنها راهه. تکیه‌کردن به پروکسی سیستمِ ویندوز هم شکننده‌ست
    -- با قطع‌شدن VPN اون تنظیم پاک می‌شه و ربات بی‌صدا از تلگرام می‌افته.
  * برای `socks5://` باید `pip install "python-telegram-bot[socks]"` نصب باشه.
  * خطای تکرارشونده‌ی «Error while getting Updates: Server disconnected
    without sending a response» یعنی پروکسی اتصالِ long-poll رو می‌بنده.
    ربات نمی‌میره (خودش دوباره وصل می‌شه)، ولی اگه زیاد تکرار شد
    `telegram_poll_timeout` رو کم کن (مثلاً ۵). پروکسی SOCKS5 معمولاً برای
    long-polling پایدارتر از پروکسی HTTP است.

این یه پروسه چهار چیز رو هم‌زمان بالا می‌آره: ربات فروش، سوپروایزر
ربات‌های مشتری‌ها، ربات‌های شخصی مشتری‌ها، و API لایسنس.

## جریان خرید (از دید مشتری)

```
/start
  └─ 🛒 خرید ربات
       ├─ پنل آماده (پنل ۱: یک ماه، پنل ۲: یک ماه دو ربات، ...)
       └─ 🎛 سفارشی  → ماه / ربات / امکانات را خودش می‌چیند
            │
            ▼
        فاکتور (دلار + تومان، ردیف‌به‌ردیف)
            │ «💳 پرداخت می‌کنم»
            ▼
        شماره کارت + مبلغ (قابل کپی)
            │ کاربر عکس رسید می‌فرستد
            ▼
        بررسی خودکار (OCR محلی)  →  صف تأیید ادمین
            │ ادمین «✅ تأیید» را می‌زند
            ▼
        لایسنس صادر می‌شود  →  ویزارد اطلاعات سرور تیم‌تاک
            │
            ▼
        لاین صدا ساخته می‌شود + ربات بالا می‌آید
```

از اجرای بعدی به بعد، ربات‌ها **خودکار** به سرورهای فعال وصل می‌شن؛
سوپروایزر از دیتابیس می‌خونه که کی باید بالا باشه.

**راه دوم: تتر (اختیاری).** کنار «💳 پرداخت می‌کنم» می‌شه «💎 پرداخت با USDT»
هم داشت: مشتری یه مبلغ یکتا می‌گیره، واریز می‌کنه، و ربات با تماشای آدرس
دریافتِ تو (بدون هیچ کلید خصوصی) لایسنس رو خودکار صادر می‌کنه. پیش‌فرض
خاموشه؛ راه‌اندازی و جزئیات: [CRYPTO_PAYMENTS.md](CRYPTO_PAYMENTS.md).

## بررسی رسید: این چیزی که هست و چیزی که نیست

بررسی خودکار **هیچ‌وقت خودش لایسنس صادر نمی‌کنه**. حتی وقتی نتیجه‌ی OCR
کامل جور باشه، سفارش می‌ره توی صف تأیید تو. دلیلش این که از یه اسکرین‌شات
فشرده‌شده‌ی تلگرام نمی‌شه با اطمینان گفت پرداخت واقعی بوده — هر ادعای
قطعی‌تری در عمل یا مشتری واقعی رو رد می‌کنه یا تقلب رو.

چیزی که واقعاً چک می‌شه:

| چک | وزن | توضیح |
|---|---|---|
| مبلغ | ۰.۴۵ | عددهای متن با مبلغ فاکتور (ریال و تومان) مقایسه می‌شن |
| ۴ رقم آخر کارت مقصد | ۰.۲۰ | توی متن رسید هست؟ |
| ساختار متن | ۰.۱۵ | کلمات کلیدی رسید بانکی |
| شماره پیگیری | ۰.۱۰ | عدد بلند پیدا شد؟ |
| تاریخ | ۰.۱۰ | تاریخ شمسی/میلادی دیده شد؟ |
| متادیتای ویرایش | −۰.۲۵ | اثر Photoshop/Canva/... توی EXIF |

**قوی‌ترین چک واقعی، تکراری‌نبودنه**: هش تصویر و شماره پیگیری با
رسیدهای قبلی مقایسه می‌شن. رایج‌ترین تقلب «فرستادن یه رسید درست، چند بار»
است، نه ساختن رسید جعلی — و این یکی قطعی گرفته می‌شه.

نتیجه به ادمین با یه پیام آماده و دو دکمه («تأیید» / «رد») می‌رسه. اگه
امتیاز از `receipt_min_score` کمتر باشه، به کاربر هم گفته می‌شه که بررسی
خودکار مشکل داشت — با این توضیح صریح که **رد نشده** و یه آدم واقعی هم
بررسیش می‌کنه.

بدون نصب tesseract هم پلتفرم کار می‌کنه؛ اون‌موقع هر رسید مستقیم می‌ره
برای بررسی دستی.

## قیمت‌گذاری

```
قیمت ماهانه = (پایه + ربات اضافه×m + امکانات) × ضریب مدت
```

> کاربر مدیر (اپراتور) از تصمیم ۲۰۲۶-۰۹-۱۶ دیگه بُعدِ قیمت یا سهمیه
> نیست: هر ربات هر چند اپراتور که لازم داره می‌تونه داشته باشه، فقط یه
> سقفِ فنیِ ۵۰ تایی توی ویزارد راه‌اندازی هست (بدون ربط به لایسنس یا
> قیمت) که فقط جلوی یه لیستِ عملاً بی‌معنی رو می‌گیره.

پیش‌فرض‌ها (همه به دلار):

| قلم | قیمت |
|---|---|
| پایه: ۱ ربات، فقط یوتیوب | ۵ |
| هر ربات اضافه | ۴ |
| ۳ ماه / ۶ ماه / ۱۲ ماه | ×۲.۸۵ / ×۵.۴ / ×۱۰.۲ (۵٪/۱۰٪/۱۵٪ تخفیف) |

امکانات (ماهانه): اینستاگرام ۲، تیک‌تاک ۱، ساندکلاد ۱، اسپاتیفای ۱.۵،
**پخش مستند ۱.۵**، دانلود ۲، حساب شخصی ۱.۵، رومینگ ۱، پروکسی ۱، alias ۱.
بسته‌ی همه‌ی سرویس‌ها ۴، بسته‌ی کامل ۹.

> پخش مستند (`md`) یه امکان کاملاً جداست که روی لایسنس اصلی سوار می‌شه:
> بدون خریدش، نه دستور `md` وجود داره و نه فرستادن یه عدد خام به مستند
> می‌رسه.

اگه کاربر همه‌ی اعضای یه بسته رو انتخاب کنه، **خودکار** قیمت بسته حساب
می‌شه — لازم نیست بدونه بسته‌ای وجود داره.

### تغییر قیمت‌ها بدون دست‌زدن به کد

`data/licensing/catalog.json` رو ویرایش کن، بعد توی ربات `/reload` بزن.
هر کلیدی که اونجا باشه روی پیش‌فرض سوار می‌شه. برای دیدن وضعیت فعلی:

```bash
python manage.py catalog
python manage.py quote 3 2 svc_instagram cap_download
```

### نرخ دلار

خودکار هر ۴ ساعت از منابع نرخ آزاد گرفته و کش می‌شه. **هیچ‌وقت به API
تکیه نمی‌کنیم**: اگه جواب نداد، آخرین نرخ کش‌شده استفاده می‌شه؛ و نرخ
دستی ادمین همیشه برنده‌ست.

```
/rate            نمایش + به‌روزرسانی
/rate 105000     نرخ دستی (تومان به ازای دلار)
/rate auto       برگشت به خودکار
```

اگه هیچ نرخی در دسترس نباشه، فقط مبلغ دلاری نشون داده می‌شه و به ادمین
هشدار می‌ره — نه اینکه یه عدد تومانی الکی ساخته بشه.

## امکانات و قفل شدنشان

هر لایسنس به‌صورت پیش‌فرض **فقط یوتیوب** داره، به‌علاوه‌ی همه‌ی دستورهای
پخش، پلی‌لیست، صف، صدا، تاریخچه و مدیریت. بقیه‌ی سرویس‌ها و امکانات
دونه‌دونه خریدنی‌ان.

قفل‌شدن **با لود نکردن** انجام می‌شه، نه با ارور دادن:

- سرویس‌های نخریده از `bot.services` حذف می‌شن، پس `w`/`p` اصلاً نمی‌بیننشون.
- دستورهای نخریده از جدول دستورها حذف می‌شن، پس درست مثل یه دستور ناموجودن
  و توی `help` هم نمی‌آن.

دلیلش: دستوری که وجود داره ولی همیشه می‌گه «نداری» هم گیج‌کننده‌ست هم
دعوت به تلاش برای دور زدن. دستوری که وجود نداره، بحثی نداره.

کاربر با `lic` داخل تیم‌تاک می‌تونه ببینه چی داره و لایسنسش تا کِی اعتبار داره.

### قاعده‌ی مهم: بدون لایسنس، هیچ‌چیز قفل نمی‌شه

اگه نه `license.json` باشه و نه `identity.json` پرچم `platform_managed`
داشته باشه، ربات **کامل و بدون محدودیت** بالا میاد. این عمدیه: نسخه‌ی
توسعه‌ی خودت و نصب‌های قبل از سیستم لایسنس نباید با آپدیت امکانات از دست
بدن.

ولی یه نمونه‌ی *مدیریت‌شده* بدون لایسنس معتبر **اجرا نمی‌شه**. بدون این
تفکیک، راه دور زدن لایسنس می‌شد «فایل لایسنس رو پاک کن».

## انقضا: دو لایه

**لحظه‌ای** — هر جا لایسنس خونده می‌شه (استارت ربات، منوی تلگرام، درخواست
API) تاریخ انقضا با دقت ثانیه چک می‌شه. لایسنسی که ساعت ۳ بعدازظهر تموم
می‌شه، ساعت ۳:۰۱ دیگه کار نمی‌کنه.

**شبانه (ساعت ۱۲ شب)** — یه جاروی کامل که کارهای سنگین و برگشت‌ناپذیر رو
انجام می‌ده:

1. یادآوری تمدید (۷، ۳ و ۱ روز قبل — هر مرحله فقط یک بار)
2. تازه-منقضی‌شده‌ها → `expired` + شروع مهلت + خاموش‌کردن ربات‌ها + بستن لاین صدا
3. مهلت‌تموم‌شده‌ها → **حذف لاین صدا + پاک‌کردن دیتای اون سرور**

قدم ۲ و ۳ جدان و این عمدیه: کاربر اول فقط سرویسش قطع می‌شه (با تمدید همه‌چیز
برمی‌گرده)، و فقط اگه `grace_days` روز (پیش‌فرض ۳) هیچ کاری نکرد، داده‌هاش
پاک می‌شه. حذف داده‌ی مشتری نباید توی ثانیه‌ی اول اتفاق بیفته.

ساعت جارو و روزهای یادآوری و مهلت، همه توی `config.json` قابل تغییرن.

```bash
python manage.py sweep     # اجرای دستی همون جارو
```

### 📊 گزارش روزانه‌ی ادمین‌ها

هر روز ساعت `daily_report_hour` (پیش‌فرض ۹ صبح، به وقت محلی سرور) یه پیام
کوتاه برای همه‌ی ادمین‌ها می‌ره، هر کس به زبان خودش:

  * ربات‌ها: در حال اجرا / خراب / مسدود (از supervisor و دیتابیس)
  * تعداد خطاهای ۲۴ ساعت اخیر `errors/errors.log` و چند «زمینه»‌ی پرتکرار.
    متنِ exception هیچ‌وقت نمی‌آد؛ متنِ توی کوتیشن (جستجو/لینک) و اسمِ
    درخواست‌دهنده هم از زمینه‌ها حذف می‌شه. خطوطِ رمزشده‌ی بیلد شمرده نمی‌شن.
  * لایسنس‌هایی که تا ۳ روز دیگه تموم می‌شن (تعداد + کلید و کاربر)
  * سفارش‌های منتظرِ تأیید
  * پرداخت‌های تتر: در انتظار و دریافت‌شده‌ی ۲۴ ساعت اخیر (فقط اگه `crypto.enabled`)

دکمه‌ی **«📊 گزارش همین الان»** توی `/admin` همون گزارش رو فوراً می‌فرسته.

| کلید `config.json` | پیش‌فرض | |
|---|---|---|
| `daily_report_enabled` | `true` | خاموش‌کردنِ ارسال صبحگاهی (دکمه همچنان کار می‌کنه) |
| `daily_report_hour` | `9` | ساعتِ ارسال، ۰ تا ۲۳ (مقدار نامعتبر = ۹) |

### 🍪 هشدارِ خودکارِ کوکیِ یوتیوب

وقتی یه ربات به «Sign in to confirm you're not a bot» یوتیوب می‌خوره، خودش
یه سیگنالِ کوچیک (`alerts.json`، حداکثر هر ۶ ساعت یک‌بار) توی پوشه‌ی خودش
می‌نویسه. license_server هر ۱۰ دقیقه پوشه‌ی ربات‌های تحتِ نظارتِ supervisor
رو نگاه می‌کنه (اگه هیچ رباتی اجرا نمی‌شه اصلاً چیزی نمی‌خونه) و برای هر
هشدارِ تازه:

  * **مالکِ لایسنس** پیام می‌گیره («ربات شما کوکی یوتیوب می‌خواد») با دکمه‌ی
    🍪 کوکی که مستقیم به منوی کوکیِ همون ربات می‌ره (بخش کوکی‌ها، `ck:menu`).
  * **همه‌ی ادمین‌ها** هم پیام می‌گیرن (مالکی که خودش ادمینه فقط یک پیام).

بعدش هشدار «رسیدگی‌شده» ثبت می‌شه (توی جدول `settings`) و تکرار نمی‌شه؛ به یه
ربات بیشتر از هر ۲۴ ساعت یک‌بار پیام داده نمی‌شه، حتی اگه مشکل ادامه داشته
باشه. اگه تلگرام در دسترس نباشه، اسکنِ بعدی دوباره تلاش می‌کنه.

**محدودیت:** رباتی که روی ماشینِ خودِ مشتری اجرا می‌شه (لایسنس اجاره‌ای،
[RENTAL.md](RENTAL.md)) همین سیگنال رو روی دیسکِ خودش می‌نویسه و سرور هیچ
دسترسی‌ای به اون دیسک نداره؛ پس برای اون‌ها هشداری نمی‌رسه و عمداً تلاشی
برای رسیدن بهشون نمی‌کنیم.

## لاین صدا

| سیستم | چطور |
|---|---|
| لینوکس | `module-null-sink` پالس‌اودیو — **ساخت و حذف برنامه‌ای**، بی‌نهایت لاین |
| ویندوز | از لاین‌های موجود Virtual Audio Cable یکی تخصیص داده می‌شه |

فعال‌سازی لایسنس یعنی: لاین ساخته می‌شه → کانفیگ نوشته می‌شه →
`license.json` نوشته می‌شه → پروسه استارت می‌شه.

غیرفعال‌سازی برعکس و **با همین ترتیب**: پروسه بسته می‌شه (اول این، وگرنه
ربات با یه لاینِ حذف‌شده کار می‌کنه) → لاین حذف می‌شه → دیتا پاک می‌شه.

توی `identity.json` همیشه به **اسم لاین** اشاره می‌شه (`"line:<slug>"`)
نه شماره‌ی دستگاه، چون شماره روی لینوکس با هر ری‌استارت پالس‌اودیو عوض
می‌شه. بعد از ریبوت، لاین‌ها خودکار بازسازی می‌شن.

راهنمای کامل لینوکس: [`INSTALL-linux.md`](INSTALL-linux.md)

## ربات شخصی مشتری

مشتری می‌تونه از @BotFather یه ربات بسازه و توکنش رو بده؛ اون ربات فقط
مال خودشه و توش ربات‌های تیم‌تاک خودش رو می‌بینه و کنترل می‌کنه
(اجرا/توقف/ری‌استارت، وضعیت، لاین صدا، لایسنس).

- فقط برای کسانی فعاله که لایسنس فعال دارن.
- ربات شخصی **فقط به صاحب توکن** جواب می‌ده؛ هر کس دیگه یه پیام کوتاه
  می‌گیره. (توکن ربات تلگرام عملاً عمومیه، پس نمی‌شه فرض کرد فقط مالک
  بهش پیام می‌ده.)
- همه‌ی ربات‌ها توی همون پروسه‌ی asyncio اجرا می‌شن، ولی هر کدوم
  `Application` خودش رو داره — پس یه توکن باطل‌شده فقط خودش رو زمین می‌زنه.
- خرید و پرداخت عمداً اینجا نیست و توی ربات فروش می‌مونه.
- توکنی که باطل/لغو بشه (از BotFather، یا خودِ ربات پاک بشه) -- چه موقعِ
  استارتِ پلتفرم چه وسطِ اجرا -- «مرده» علامت می‌خوره: اپش متوقف می‌شه،
  دیگه هیچ‌وقت (حتی بعد از ری‌استارتِ کامل) دوباره امتحان نمی‌شه، و
  مالکش از طریقِ ربات فروش (چون ربات خودش دیگه جواب نمی‌ده) یک‌بار
  خبردار می‌شه که یه توکنِ تازه بفرسته. قطعیِ موقتِ شبکه/پروکسی این
  علامت رو نمی‌خوره -- فقط توکنِ واقعاً باطل.

## نسخه‌ی self-host (بازنشسته)

قبلاً اگه مشتری می‌خواست ربات رو روی سیستم خودش اجرا کنه، یه API لایسنسِ
جدا (`POST /activate`/`/refresh`) یه توکنِ امضاشده‌ی Ed25519 (۷ روزه) بهش
می‌داد و `license.json` از محتوای همون توکن نوشته می‌شد -- با یه سقفِ
`max_bots` دستگاهِ متفاوت (`machine_id`) به ازای هر لایسنس.

این مسیر عمداً **پیش‌فرض خاموش** بود (`selfhost_enabled: false`) و هیچ
لایسنسِ واقعاً فروخته‌شده‌ای ازش استفاده نکرده بود -- تنها لایسنسِ
self-host بودنِ ممکن یعنی بخش `license` توی `identity.json`، که هیچ نصبِ
واقعی‌ای نداشتش. با تصمیمِ تثبیتِ پلتفرم روی دو مسیرِ واقعی (میزبانیِ
مستقیم روی سرورِ خودمون، و لایسنسِ اجاره‌ای مقابلِ Cloudflare KV --
`docs/RENTAL.md`)، این مسیر کامل حذف شد: `licensing/api.py`،
`core/license_client.py`، اندپوینت‌های `/activate`/`/refresh`/`/pubkey`ِ
سرورِ HTTP، بخشِ توکن‌بررسیِ `core/license_gate.py`، و دکمه‌ی «دستگاه‌های
self-host» توی پنلِ ادمین -- همه برداشته شدن. تاریخچه‌ی کاملش توی گیته.

جفت‌کلید Ed25519 (`data/licensing/keys/`) هنوز سرِ جاشه، ولی الان تنها
مصرف‌کننده‌ش کلیدِ امضای Cloudflare Worker است (`manage.py deploy-worker`/
`worker-key`؛ ببین `docs/RENTAL.md`).

## دستورهای ادمین در تلگرام

```
/admin                  پنل (آمار، صف تأیید، تیکت‌ها، نرخ، لاین‌ها، لایسنس‌ها، ...)

/rate [عدد|auto]        نرخ دلار
/card <شماره> | <نام> | <بانک>
/alllicenses            همه‌ی لایسنس‌های سرور -- فیلتر، صفحه‌بندی، جست‌وجو
/grant <user_id> <ماه> <ربات> [امکانات...]    لایسنس دستی
/extend <کلید> <ماه>    تمدید دستی
/suspend <کلید> [دلیل]  تعلیق (لاین بسته می‌شود، دیتا می‌ماند)
/resume <کلید>          رفع تعلیق
/revoke <کلید> [دلیل]   لغو کامل + پاک‌کردن دیتا

/lines                  لاین‌های صدا

/quote <ماه> <ربات> [امکانات...]              قیمتِ یه ترکیب
/rentalreset <کلید> [روز]                     ریستِ لایسنسِ اجاره‌ای
/broadcast              پیام همگانی (متن/عکس/ویدیو/صدا/فایل) به همه یا زیرمجموعه
```

همه‌ی این‌ها از ترمینال هم در دسترسن (`python manage.py --help`) -- به‌جز
`/broadcast` و `/readerrors` که ذاتاً کارِ تلگرامن (پیام‌رسانی و فایل).

### هر عملیاتِ ادمین از پنل هم با دکمه در دسترسه

هیچ‌کدوم از این‌ها لازم نیست از حفظ تایپ بشه: `/admin` -> دکمه، و هر
پارامتری (کلیدِ لایسنس، تعداد ماه، لیستِ امکانات، آیدیِ تلگرام، تعداد
روز) یا با دکمه انتخاب می‌شه یا با یه سؤالِ ساده پرسیده می‌شه (مثلِ
ویزاردِ همیشگیِ راه‌اندازیِ ربات). مثلاً:

  * **🔑 لایسنس‌ها**: لیستِ همه‌ی لایسنس‌های سرور با فیلترِ وضعیت
    (فعال/منقضی/معلق/متوقف/لغوشده/همه) و صفحه‌بندی، به‌علاوه‌ی «🔍 پیداکردن»
    که با کلید یا آیدیِ تلگرام جست‌وجو می‌کنه. هر ردیف همون کارتِ همیشگیِ
    لایسنس رو باز می‌کنه.
  * روی کارتِ هر لایسنس (وقتی ادمین بازش کرده، حتی اگه مالِ خودش نباشه):
    دکمه‌های تمدیدِ سریع (+۱/+۳/+۱۲ ماه)، تعلیق/رفعِ تعلیق، لغو (با تأیید،
    چون داده‌ی ربات‌هاش همون لحظه پاک می‌شه)، و **🗑 حذفِ لایسنس**
    (برگشت‌ناپذیر، جدا از لغو -- پایین‌تر توضیح داده شده).
  * **🧮 محاسبه‌ی قیمت** و **📋 کاتالوگ**: کاتالوگ مستقیم نشون داده می‌شه؛
    محاسبه‌ی قیمت یه ویزاردِ سه‌سؤالیه (ماه -> ربات -> امکانات).
  * **🎁 صدورِ لایسنس**: معادلِ دکمه‌ایِ `/grant` -- آیدیِ تلگرام، ماه،
    ربات، امکانات، هر کدوم با یه سؤال.
  * **🔄 ریستِ لایسنسِ اجاره‌ای**: کلید رو می‌پرسه، بعد روزهای اعتبار رو
    با دکمه انتخاب می‌کنی؛ اگه لایسنس به یه دستگاه بایند شده، به‌جای
    پرچمِ `--force` یه دکمه‌ی تأیید نشون داده می‌شه. لایسنسِ
    `protected_licences` دقیقاً مثلِ CLI رد می‌شه.
  * **لاین‌های صدا**: کنارِ لیستِ همیشگی، «➕ افزودن» (اسمِ لاین با یه
    پیام پرسیده می‌شه)، دکمه‌ی 🗑 روی هر لاین (با تأیید)، و «🔁 بازسازیِ
    لاین‌های ازبین‌رفته».
  * **🔓 بازکردنِ لاگِ خطا**: دکمه یا کپشنِ `/readerrors` روی فایل؛ ادمین
    `errors.log` رو به‌عنوانِ سند می‌فرسته و یه `.txt` رمزگشایی‌شده پس
    می‌گیره (فقط ادمین؛ همون کلید و همون حلقه‌ی رمزگشایی که
    `manage.py read-errors` استفاده می‌کنه).
  * **📣 پیام همگانی**: پایین‌تر توضیح داده شده.

### 🧹 پاکسازی پسماند (`/gc`)

فقط ادمین، فقط ربات فروش: `/gc` یا دکمه‌ی «🧹 پاکسازی» توی `/admin`؛ از
ترمینال `python manage.py gc [--apply] [--categories a,b] [--retention-days N]`
(پیش‌فرض فقط گزارش؛ `--apply` تایپ `yes` می‌خواد). هر دو `licensing/gc.py`
رو صدا می‌زنن. اول اسکن (فقط خوندن)، بعد مرور هر دسته، تأیید، اجرا.
اجرا قبل از پاک‌کردن دوباره اسکن می‌کنه و فقط موردهای هنوز-امن رو پاک می‌کنه.

| دسته | چی و کی |
|---|---|
| `instances` | ردیف نمونه‌ی `removed` (یا `missing` با لایسنسِ تمام‌شده) بعد از ۳۰ روز |
| `folders` | پوشه‌ی `data/<host>_<port>/<bot>` با `identity.json` بدون ردیف دیتابیس، و پوشه‌ی سرورِ خالی (حداقل ۱ روز قدیمی) |
| `lines` | لاینِ ساخته‌شده توسط provisioning که هیچ نمونه‌ای صاحبش نیست (لاینِ دستیِ ادمین دست‌نخورده) |
| `licenses` | `expired` بعد از `grace_days` + ۹۰ روز، یا `revoked` بیش از ۹۰ روز، بدون نمونه‌ی زنده؛ با همون هسته‌ی «🗑 حذف لایسنس» |
| `orders` | سفارش تأییدنشده (`pending`/`awaiting_receipt`/`rejected`/`cancelled`/`expired`) بیش از ۳۰ روز + عکس رسیدش |
| `receipts` | فایل رسید بدون سفارش |
| `events` | قدیمی‌تر از ۱۸۰ روز؛ فقط گزارش (audit trail)، حذف فقط با گزینه‌ی `delete_events` |
| `logs` | فایل‌های `errors/` قدیمی‌تر از ۳۰ روز |
| `temp` | `*.tmp` (۱ روز) و `*.bak` (۷ روز) توی `data/` به‌جز `licensing/` |
| `downloads` | فایل‌های `downloads/` ربات‌ها قدیمی‌تر از ۷ روز |

قاعده‌های ثابت: لایسنسِ `protected_licences` (و TT-EQ4F)، owner،
«admin unlimited» و هر لایسنسِ active/paused/suspended هیچ‌وقت کاندید
نمی‌شن؛ `keys/`، `config.json`، دیتابیس و `_machine_id` لمس نمی‌شن؛ هر
مسیر باید زیرِ ریشه‌ی مجازش باشه. نمونه‌ی `missing` با لایسنسِ فعال
(مشتری شاید بازتأمین بخواد) پاک نمی‌شه و توی «⚠️ نیازمند توجه» نشون داده
می‌شه.

### چیزهایی که عمداً توی تلگرام نیستن

این‌ها لایسنس/مشتری نیستن، ابزارِ توسعه/زیرساختن، و ریسکِ گذاشتنشون
توی چتِ تلگرام (لو رفتنِ رازها، یا یه دکمه‌ی خطرناک که راحت لمس بشه)
بیشتر از فایده‌شه؛ فقط از ترمینال:

`devices`، `doctor`، `selftest`، `build-check`، `cf-token` (توکنِ API
کلادفلر -- یه راز)، `deploy-worker`، `error-keys` (ساختنِ کلیدِ تازه‌ی
رمزنگاریِ لاگ -- کلیدهای قدیمی رو بی‌اثر می‌کنه)، `worker-key` (کلیدِ
خصوصیِ امضا -- یه راز).

### 📣 پیام همگانی

`/broadcast` یا دکمه‌ی مشابه توی `/admin`: ادمین هر پیامی (متن، عکس،
ویدیو، ویس، فایل) بفرسته، همون با `copy_message` عیناً برای مخاطب‌ها
کپی می‌شه -- فرمت‌بندی و رسانه دست‌نخورده می‌مونه. بعدش مخاطب رو انتخاب
می‌کنی (همه / لایسنسِ فعال دارن / ندارن)، تعداد گیرنده و پیش‌نمایش رو
می‌بینی و تأیید می‌کنی.

ارسال یه تسکِ پس‌زمینه‌ست (بقیه‌ی ربات قفل نمی‌شه)، یه‌بار در یک زمان،
با نرخِ حدودِ ۲۵ پیام در ثانیه و رعایتِ کاملِ `RetryAfter` تلگرام. دکمه‌ی
لغو هر لحظه متوقفش می‌کنه. کاربری که ربات رو بلاک کرده (یا هیچ‌وقت
استارت نزده) توی ستونِ `users.bot_blocked_at` ثبت و از پیام‌های همگانیِ
بعدی حذف می‌شه -- تا دوباره خودش با ربات حرف بزنه (اولین آپدیتِ بعدیش
خودکار پاکش می‌کنه). در آخر ادمین گزارش می‌گیره: فرستاده‌شده/بلاک/ناموفق.

### هیچ خطای خامی به کاربر یا ادمین نشون داده نمی‌شه

هر `except ... as e` که قراره نتیجه‌ش توی چت نشون داده بشه، خطای واقعی
رو با `logging_setup.log_exception`/`log_debug` توی `errors/errors.log`
ثبت می‌کنه و فقط یه پیامِ عمومی و ترجمه‌شده می‌فرسته -- هیچ‌وقت
`str(e)` یا traceback مستقیم. استثنائاتِ خودِ کد (مثلِ `WizardError`،
`PromoError`، `AudioLineError`) که از اول با یه پیامِ کوتاه و امن
ساخته شدن، فرقی دارن و همون پیامشون نشون داده می‌شه.

### «🎁 ربات نامحدود» توی پنل

دکمه‌ی «ربات نامحدود» توی `/admin` یه ربات کامل رو بدون پرداخت و بدون
محدودیت راه می‌اندازه، توی یه گفت‌وگوی پیوسته:

  ۱. آیدی عددی تلگرامِ مالک (یا «-» یعنی خودت)
  ۲. لایسنس با همه‌ی امکانات، سهمیه‌ی عملاً نامحدود و انقضای ۱۰۰ ساله صادر می‌شه
  ۳. بعد همون ویزارد همیشگی می‌پرسه: هاست و پورت تیم‌تاک، نیک‌نیم،
     **یوزرنیم و پسوردِ لاگین ربات**، آیدی و پسورد کانال، و اپراتورها
  ۴. با تأیید، لاین صدا ساخته و ربات اجرا می‌شه و مالک هم خبردار می‌شه

چرا لایسنس صادر می‌شه و نه «ربات بدون لایسنس»: ربات بدون `license.json`
معتبر اصلاً بالا نمی‌آد و این عمدیه (`core/license_gate.py`). یه سوییچِ
«لایسنس لازم نیست» همون راه فراریه که اونجا نوشته نباید وجود داشته باشه --
هرکس دیگه‌ای هم می‌تونست پیداش کنه. لایسنس ۱۰۰ ساله از بیرون دقیقاً همون
«بدون محدودیت» است، بدون ضعیف‌کردن قفل.

معادل ترمینالیش: `python manage.py self-license <telegram_id> <bot_dir>`

### دکمه‌ی پیش‌فرض کنار پرسش‌های ویزارد

هر مرحله‌ای که جواب اجباری نداره یه دکمه کنار پیام داره: پورت
(`10333`)، نیک‌نیم، آیدی کانال (`1`)، «پسورد نداره» و «فعلاً هیچ‌کس».
آدرس سرور و یوزر/پسِ ربات دکمه ندارن چون قابل حدس‌زدن نیستن.

دکمه همون جواب رو از مسیر همیشگیِ متن رد می‌کنه، پس اعتبارسنجی‌ها
(عدد بودن پورت، سقف اپراتورها) یک‌جا می‌مونن و دو نسخه نمی‌شن.

### حذف لایسنس و ویرایش ربات

  * **🗑 حذف لایسنس** (فقط ادمین، توی کارت هر لایسنس): ربات‌ها خاموش،
    لاین صداشون آزاد، دیتاشون پاک، و بعد خودِ لایسنس و ردیف ربات‌هاش از
    دیتابیس حذف می‌شن. برگشت نداره. اگه می‌خوای سابقه بمونه `/revoke`
    رو بزن که لایسنس رو «لغوشده» نگه می‌داره. جدول `events` در هر دو
    حالت دست‌نخورده می‌مونه.
  * **✏️ ویرایش** (توی کارت هر ربات): همون ویزارد، ولی از مقدارهای فعلی
    پر شده و هر مرحله دکمه‌ی «همین بمونه» داره. آخرش کانفیگ روی دیسک
    دوباره نوشته و ربات ری‌استارت می‌شه. slug و لاین صدا عوض نمی‌شن.
  * **🗑 حذف ربات** از قبل بود و برای ادمین هم کار می‌کنه.

## پشتیبانی مشتری

دکمه‌ی «📨 پشتیبانی» یه تیکت می‌سازه که مستقیم برای ادمین می‌ره، همراه با
آیدی کاربر و شماره‌ی آخرین سفارشش. جواب با `/reply <id> <متن>` برمی‌گرده
به همون چت.

این عمداً یه راه ارتباطی مستقل از جریان پرداخته: اگه بررسی خودکار اشتباه
کرده یا جای دیگه‌ای مشکلی پیش آمده، کاربر نباید گیر کنه.

### لاگ خطای مشتری

لاگ خطا روی سیستم مشتری **رمز** نوشته می‌شه — چون همون لاگ
مسیرهای داخلی، اسم سرویس‌ها و جزئیات پیاده‌سازی رو لو می‌ده. مشتری
فایل `errors/errors.log` رو می‌فرسته، تو بازش می‌کنی:

```
python manage.py read-errors errors.log            # روی صفحه
python manage.py read-errors errors.log out.txt    # توی فایل
```

کلیدی که داخل بیلد مشتریه فقط می‌تونه *رمز کنه*؛ بازکردن فقط با
کلید خصوصییه که فقط پیش توئه. یعنی حتی خود مشتری هم لاگ
خودش رو نمی‌تونه بخونه.

قبل از اولین بیلد، یه بار کلید بساز و عمومیش رو توی
`core/error_crypt.py` بذار:

```
python manage.py error-keys
```

تا وقتی این کلید خالیه، `build-check` بیلد رو رد می‌کنه: بدونش لاگ
خام روی سیستم مشتری می‌نشینه. روی اجرای عادی (توسعه) رمزنگاری
خاموشه، وگرنه خودت هم موقع دیباگ لاگت رو نمی‌خوندی.

پسورد تیم‌تاک ربات‌ها قابل هش‌کردن نیست (ربات باید باهاش لاگین کنه) و
به‌صورت متن ذخیره می‌شه؛ دیتابیس و identity با `chmod 600` نوشته می‌شن.

بکاپ = کپی کل پوشه‌ی `data/`. مهم‌ترین قلمش `keys/private.key` است: با
گم‌شدنش، امضای لایسنسِ اجاره‌ای (Cloudflare Worker) دیگه با کلیدِ عمومیِ
جا‌داده‌شده توی بیلدهای موجود جور درنمی‌آد و باید دوباره `deploy-worker`
بزنی و کلید عمومیِ جدید رو توی بیلدهای بعدی جا بدی.
