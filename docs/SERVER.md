# سرور: چی بخرم و چند ربات توش جا می‌شه

## خلاصه‌ی جواب

**یک VPS لینوکسی، خارج از ایران، ۴ گیگ رم / ۲ هسته** برای شروع کافیه و
حدود **۲۵ تا ۳۰ ربات** جا می‌ده. همین یه سرور، هم پلتفرم لایسنس و هم
همه‌ی ربات‌های مشتری‌ها رو اجرا می‌کنه — به سرور دوم نیازی نیست.

---

## اعداد از کجا آمدند

مصرف حافظه‌ی یک ربات، اندازه‌گیری‌شده (نه تخمین):

| مرحله | حافظه |
|---|---|
| پایتون خالی | ۱۳ مگابایت |
| + ماژول‌های core | ۱۷ |
| + ۵ سرویس (yt-dlp) | ۴۶ |
| + ۹۸ دستور | ۵۹ |
| + یک نمونه‌ی mpv | ۶۹ |
| **+ در حال پخش صدا** | **۷۶ مگابایت** |

روی لینوکس معمولاً کمی کمتره. با احتساب سرریز، **۱۰۰ مگابایت به ازای هر
ربات** عدد امنیه.

### ظرفیت

| رم | سیستم‌عامل + سرویس‌ها | باقی‌مانده | تعداد ربات |
|---|---|---|---|
| ۲ گیگ | ~۵۰۰ مگ | ۱.۵ گیگ | **~۱۵** |
| ۴ گیگ | ~۵۰۰ مگ | ۳.۵ گیگ | **~۳۰** |
| ۸ گیگ | ~۶۰۰ مگ | ۷.۴ گیگ | **~۷۰** |
| ۱۶ گیگ | ~۷۰۰ مگ | ۱۵ گیگ | **~۱۴۰** |

### پردازنده

دیکود صدا با `vid=no` تقریباً رایگانه (چند درصد از یک هسته). اوج مصرف
مال استخراج لینک (yt-dlp) است که بیشترش انتظار شبکه‌ست، نه پردازش.

- **۲ هسته** تا ~۳۰ ربات
- **۴ هسته** تا ~۷۰ ربات

### پهنای باند — این محدودکننده‌ی واقعیه

هر ربات در حال پخش تقریباً ۱۲۸ کیلوبیت بر ثانیه دانلود می‌کنه و همون‌قدر
هم به تیم‌تاک آپلود: حدود **۳۲ کیلوبایت بر ثانیه رفت‌وبرگشت**.

| تعداد ربات | سرعت لحظه‌ای | مصرف ماهانه اگر ۲۴ ساعته پخش کنن |
|---|---|---|
| ۱۰ | ~۲.۶ مگابیت | ~۸۰۰ گیگ |
| ۳۰ | ~۷.۷ مگابیت | ~۲.۴ ترابایت |
| ۷۰ | ~۱۸ مگابیت | ~۵.۶ ترابایت |

سرعت خط اصلاً مسئله نیست (هر VPS معمولی ۱ گیگابیت داره)، ولی **سقف ترافیک
ماهانه** مهمه. قبل از خرید حتماً نگاه کن پلن چقدر ترافیک می‌ده. در عمل
ربات‌ها ۲۴ ساعته پخش نمی‌کنن، پس مصرف واقعی معمولاً یک‌سوم تا نصف این
جدوله — ولی برای بدترین حالت برنامه‌ریزی کن.

## معیارهای انتخاب (به ترتیب اهمیت)

**۱. خارج از ایران باشه.** این مهم‌ترین شرطه. سرور باید بدون پروکسی به
یوتیوب برسه. از IP ایران یا یوتیوب جواب نمی‌ده یا خیلی زود می‌گه «ربات
هستی» — و اون‌وقت باید پروکسی بذاری که هم کند می‌کنه هم یه نقطه‌ی خرابی
اضافه می‌سازه.

**۲. ترافیک ماهانه‌ی کافی.** جدول بالا. پلن‌های «نامحدود» معمولاً بعد از
یه حدی کند می‌شن؛ عدد صریح بهتر از «نامحدود»ه.

**۳. رم واقعی، نه اشتراکی.** بعضی پلن‌های ارزون رم را overcommit می‌کنن.
با ۳۰ پروسه‌ی زنده، این خودش رو به‌صورت کندی و OOM نشون می‌ده.

**۴. راه پرداخت.** از ایران این معمولاً سخت‌ترین بخشه. گزینه‌ها: ریسلرهای
ایرانی که سرور خارج می‌فروشن و ریالی می‌گیرن، یا پرداخت با رمزارز.
ریسلرها گران‌ترن ولی دردسر پرداخت ندارن.

**۵. لوکیشن نزدیک به مشتری‌ها.** تأخیر بین سرور تو و سرور تیم‌تاک مشتری
روی کیفیت صدا اثر داره. برای کاربران ایرانی، اروپا (آلمان، هلند، فرانسه)
معمولاً بهتر از آمریکاست.

> **قیمت‌ها را عمداً ننوشتم.** قیمت VPS مرتب عوض می‌شه و هر عددی که اینجا
> بنویسم خیلی زود غلط می‌شه. با مشخصات بالا (۴ گیگ / ۲ هسته / چند ترابایت
> ترافیک / اروپا) قیمت روز رو مقایسه کن.

## اقتصاد کار

هزینه‌ی سرور خودکار توی قیمت هر ربات حساب می‌شه. توی
`data/licensing/catalog.json`:

```json
"server": {
  "monthly_usd": 12.0,
  "capacity_bots": 25,
  "overhead_multiplier": 1.5
}
```

سهم هر ربات = `12 / 25 × 1.5` = **۰.۷۲ دلار در ماه**، که به‌عنوان یه ردیف
جدا توی فاکتور می‌آد. یعنی وقتی سرور رو عوض یا بزرگ کردی، فقط همین دو عدد
رو به‌روز می‌کنی و همه‌ی قیمت‌ها خودشون درست می‌شن.

با پیش‌فرض‌های فعلی:

| پنل | ماهانه | سهم سرور | حاشیه‌ی تو |
|---|---|---|---|
| ۱ ماه، ۱ کاربر، ۱ ربات | ۵.۷۲ دلار | ۰.۷۲ | ۵.۰۰ |
| ۱ ماه، ۲ کاربر، ۲ ربات | ۱۲.۴۴ دلار | ۱.۴۴ | ۱۱.۰۰ |
| بسته‌ی کامل، ۲ ربات | ۲۳.۴۴ دلار | ۱.۴۴ | ۲۲.۰۰ |

نقطه‌ی سربه‌سر: با سرور ۱۲ دلاری، **سه مشتریِ پنل ۱** کل اجاره‌ی سرور رو
درمی‌آرن. بقیه‌ش سوده.

```bash
python manage.py catalog      # همه‌ی قیمت‌ها و ظرفیت‌ها
python manage.py quote 3 2 2  # فاکتور یه ترکیب دلخواه
```

## نصب روی سرور تازه

```bash
git clone <repo> /opt/ttbot && cd /opt/ttbot
bash deploy/install-linux.sh
```

بعد `libTeamTalk5.so` رو توی `core/teamtalk/` بذار (تنها چیزی که خودکار نصب
نمی‌شه — لایسنس خودش رو داره)، و:

```bash
python license_server.py --init     # فایل‌های کانفیگ
# توکن ربات و آیدی تلگرامت را توی data/licensing/config.json بنویس
python license_server.py --check    # همه‌چیز آماده‌ست؟
systemctl --user enable --now ttbot-license
```

به‌جای این قدم‌های دستی می‌شه `python configure.py` زد؛ همه‌ی اینا (و پروکسی،
کارت، Cloudflare، لایسنس مالک) رو قدم‌به‌قدم می‌پرسه: [`CONFIGURE.md`](CONFIGURE.md).

جزئیات کامل: [`INSTALL-linux.md`](INSTALL-linux.md)

## مشتری هیچ فایلی نمی‌گیره

این دقیقاً همون چیزیه که خواسته شده و از قبل همین‌طور کار می‌کنه:

```
مشتری در تلگرام /start می‌زند
  → پنل انتخاب می‌کند و پرداخت می‌کند
  → تو تأیید می‌کنی
  → اطلاعات سرور تیم‌تاکش را در همان چت وارد می‌کند
  → سرور تو: لاین صدا می‌سازد، کانفیگ می‌نویسد، پروسه را بالا می‌آورد
  → ربات وارد کانال او می‌شود
```

هیچ `.exe` ای، هیچ فایلی، هیچ نصبی سمت مشتری نیست. از دفعه‌ی بعد هم
سوپروایزر خودش ربات‌ها را بالا نگه می‌دارد — بعد از ریبوت سرور هم لاین‌های
صدا بازسازی می‌شوند و همه‌چیز خودکار برمی‌گردد.

نسخه‌ی self-host (کلاینتی که مستقیم به یه API لایسنسِ خودمون توکن می‌گرفت)
بازنشسته شده؛ فقط دو مسیر می‌مونه: میزبانی روی سرور خودمون (همینه، بالا) و
لایسنس اجاره‌ای در برابر Cloudflare KV (`docs/RENTAL.md`).

## وقتی سرور پر شد

۱. `capacity_bots` رو توی کاتالوگ به عدد واقعی برسون (قیمت‌ها خودکار درست می‌شن).
۲. سرور رو بزرگ‌تر کن (ساده‌ترین راه).
۳. یا یه سرور دوم بگیر و ربات‌ها رو پخش کن — پلتفرم فعلاً تک‌سروره، پس
   این نیاز به یه تغییر کوچک داره (جدول `instances` باید یه ستون
   `server_id` بگیره).

برای دیدن وضعیت فعلی:

```bash
python manage.py instances
python manage.py lines
free -h && uptime
```
