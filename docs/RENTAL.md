# اجاره‌ی ربات بدون سرور

برای وقتی که می‌خوای ربات رو یه مدت مشخص به کسی بدی و بتونی هر لحظه
لغوش کنی — بدون این‌که سروری داشته باشی.

## اول: چیزی که این *نمی‌کنه*

نرم‌افزاری که روی کامپیوتر یه نفر دیگه اجرا می‌شه، در نهایت مال اونه. یه
مهاجم مصمم با دیس‌اسمبلر همیشه برنده می‌شه — این واقعیتِ همه‌ی
نرم‌افزارهای دنیاست، نه ضعف پایتون.

کاری که این سیستم می‌کنه:

  * دور زدنش رو از خریدن گرون‌تر می‌کنه
  * **لغو از راه دور** رو ممکن می‌کنه (مهم‌ترین قابلیت)
  * نشون می‌ده لایسنس داره روی چند دستگاه می‌چرخه

## معماری

```
ادمین                    Cloudflare Worker            ربات مشتری
  |                            |                          |
  | manage.py rental 30        |                          |
  |--> کلید TT-XXXX            |                          |
  |                            |                          |
  | wrangler kv put ---------> | KV: license:TT-XXXX      |
  |                            |                          |
  |                            | <---- POST /check -------|  هر بار استارت
  |                            |       {key, fingerprint} |  + هر ساعت
  |                            |                          |
  |                            | ---- payload امضاشده --->|  راستی‌آزمایی با
  |                            |                          |  کلید داخل کد
  | wrangler kv delete ------> | (لغو فوری)               |
```

کلید خصوصی **هیچ‌وقت** از کامپیوتر تو بیرون نمی‌ره جز به‌صورت secret
داخل Cloudflare. کلید عمومی داخل کد کلاینته.

## راه‌اندازی (یک‌بار)

```bash
npm install -g wrangler
wrangler login
```

اگه `npm install` با ECONNRESET خطا داد، پروکسی npm تنظیم نشده:

```bash
npm config set proxy http://10.10.14.1:8080
npm config set https-proxy http://10.10.14.1:8080
```

بعد از لاگین، بقیه‌ش خودکاره:

```bash
python manage.py deploy-worker
```

این ساخت KV، نوشتن شناسه‌ش توی `wrangler.toml`، گذاشتن کلید امضا،
دیپلوی، و نشوندن آدرس Worker توی `core/license_key.py` رو انجام می‌ده.
دوباره زدنش هم مشکلی نداره — از هر جا که مونده ادامه می‌ده.

### ساب‌دامین workers.dev

بار اول ممکنه بگه حساب هنوز ساب‌دامین نداره. این یه انتخاب **یک‌باره‌ی
حسابه** و اسمش توی آدرس عمومیت میاد، پس اسکریپت خودش انتخابش نمی‌کنه:

```bash
cd deploy && wrangler deploy
```

به سؤال «register a workers.dev subdomain» جواب `y` بده و اسم رو انتخاب
کن. بعدش `python manage.py deploy-worker` رو دوباره بزن.

## اجاره دادن (هر بار)

```bash
python manage.py rental 30 --note "برای علی"
```

کلید و دستور `wrangler kv put` رو می‌ده. اجراش کن، کلید رو به مشتری بده.

مشتری کلید رو توی `data/licensing/rental.json` می‌ذاره:

```json
{"key": "TT-XXXX-XXXX-XXXX", "username": "botuser", "password": "botpass"}
```

## لغو فوری

```bash
wrangler kv key delete --binding=LICENSES "license:TT-XXXX-XXXX-XXXX"
```

دفعه‌ی بعد که ربات چک می‌کنه (حداکثر یک ساعت بعد) می‌خوابه.

## قبل از تحویل بیلد

```bash
python manage.py build-check
```

تا وقتی این ✅ نده، بیلد رو نفرست. چک می‌کنه کلید داخل کد هست و آدرس
سرویس واقعیه، و یادآوری می‌کنه `private.key` نباید توی بسته باشه.

## پنج حمله‌ای که بسته شده

| حمله | چرا کار نمی‌کنه |
|---|---|
| تعویض `license_public.key` با کلید خودش | کلید از `core/license_key.py` میاد که با compile داخل باینریه. وقتی بیلد قفل‌شده باشه، منابع فایلی/محیطی **اصلاً خونده نمی‌شن** |
| عقب‌بردن ساعت ویندوز | زمان از هدر `Date` پاسخ سرور خونده می‌شه، نه از ساعت لوکال |
| قطع‌کردن کابل شبکه | هیچ مسیر آفلاینی نیست. «نشد چک کنیم» = «اجازه نداری» |
| کلون‌کردن ایمیج ویندوز | fingerprint از ماشین **+ یوزر/پس** ساخته می‌شه، نه فقط machine_id |
| دستکاری پاسخ سرور | امضای Ed25519 روی بایت‌های دقیق payload |

هر پنج مورد توی تست واقعی بررسی شدن (نه فقط تئوری).

## اشتراک‌گذاری رو ببین

Worker هر fingerprint ای که یه کلید رو چک کرده ثبت می‌کنه:

```bash
wrangler kv key get --binding=LICENSES "seen:TT-XXXX-XXXX-XXXX"
```

چند تا fingerprint مختلف یعنی لایسنس داره پخش می‌شه. عمداً خودکار
مسدود نمی‌شه — تصمیمش با توئه، نه با کد.

## مشتری می‌گه «لایسنسم کار نمی‌کنه»

اول بپرس **عین پیام** چی بوده؛ دو حالت کاملاً متفاوتن:

| پیام | یعنی |
|---|---|
| «این لایسنس فعال نیست یا لغو شده» | خودِ سرویس رد کرده — کلید رو روی KV چک کن |
| «سرویس لایسنس در دسترس نیست» | شبکه/کلادفلر جلوی درخواست رو گرفته — لایسنس سالمه |

قبلاً هر دو یه پیام می‌دادن: کلادفلر برای بلاک‌های خودش هم 403
می‌ده (bot-check، WAF، rate limit) و ربات اون رو «لغو شده» حساب می‌کرد.
الان فقط وقتی «لغو شده» گفته می‌شه که پاسخ، JSON خودِ سرویس باشه.

برای دیدن جزئیات، لاگ خطای مشتری رو بگیر و بازش کن:

```bash
python manage.py read-errors errors.log
```

## چیزهایی که سرور از ربات اجاره‌ای نمی‌بینه

رباتِ اجاره‌ای روی ماشینِ مشتریه و سرور به دیسک و پروسه‌ش دسترسی نداره، پس
هر چیزی که فقط از روی «نگاه‌کردن به ربات» کار می‌کنه برای اون‌ها کار
نمی‌کنه: گزارش روزانه‌ی ربات‌های در حال اجرا و هشدارِ خودکارِ کوکیِ یوتیوب
فقط ربات‌های میزبانی‌شده‌ی خودت رو پوشش می‌دن (توضیحش توی
[LICENSING.md](LICENSING.md)). مشتریِ اجاره‌ای باید خودش کوکی رو بذاره.

## یادت باشه

«سخت‌گیر برای همه» فعاله: **هیچ** لایسنسی بدون اتصال زنده کار نمی‌کنه.
یعنی یه قطعی ساده‌ی اینترنت همه‌ی ربات‌ها رو می‌خوابونه. اگه بعداً
خواستی برای مشتری‌های عادی نرمش بدی، `RECHECK_SECONDS` و مسیر
`LicenseUnreachable` توی `core/license_remote.py` همون نقطه‌ست.
