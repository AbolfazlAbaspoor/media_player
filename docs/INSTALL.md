# نصب یک‌مرحله‌ای (install.py)

`install.py` یه اسکریپتِ بوت‌استرپِ تک‌فایلیه (فقط stdlib، بدون هیچ
وابستگیِ خارجی برای خودِ اسکریپت) که از پوشه‌ی پروژه، روی یه سیستم تازه
(ویندوز یا لینوکس)، هر چی ربات برای اجرا از سورس لازم داره رو فراهم
می‌کنه:

- وابستگی‌های پایتون (`requirements.txt`، و اختیاری `requirements-license.txt`)
- ffmpeg
- libmpv
- SDK تیم‌تاک
- یه جاوااسکریپت‌رانتایم برای yt-dlp (`deno` ترجیح داده می‌شه)
- `pulseaudio-utils` روی لینوکس (لاین‌های صدا)
- اختیاری: `xray-core` (برای یه فیچرِ V2Ray به‌ازای هر ربات که هنوز پیاده نشده)

پیش‌نیازش فقط پایتون ۳.۹+ نصب‌شده‌ست؛ خودِ نصبِ پایتون کارِ این اسکریپت
نیست (چون خودش با پایتون اجرا می‌شه).

```bash
python install.py                          # همه‌چیزِ پیش‌فرض
python install.py --dry-run                # فقط پلن؛ هیچ دانلود/تغییری انجام نمی‌ده
python install.py --components ffmpeg,libmpv
python install.py --with-licensing --venv .venv
```

> **بعد از نصب:** برای تنظیم کل پروژه (توکن ربات فروش، پروکسی، ادمین‌ها،
> کارت، Cloudflare، اولین ربات و لایسنس مالک) فقط `python configure.py`
> رو بزن -- ببین [`docs/CONFIGURE.md`](CONFIGURE.md). خودش `install.py` رو
> برای چیزهای نصب‌نشده صدا می‌زنه.

روی ویندوز همین دستورها با `python` (یا `py`) عادی کار می‌کنن. روی لینوکس
معمولاً `python3 install.py ...`.

---

## چرا این اسکریپت

قبلش «چیزهایی که pip نصب نمی‌کنه» (`requirements.txt` بالای فایل) فقط
توضیح داده می‌شدن، نه خودکار انجام. برای هر مشتری/سرور جدید یه چک‌لیستِ
دستی بود: SDK رو از bearware.dk بگیر، ffmpeg رو دانلود کن، libmpv رو
apt کن، بفهم yt-dlp چرا از یوتیوب هشدار می‌ده... این اسکریپت همون
چک‌لیست رو خودکار می‌کنه، idempotent (چند بار زدنش بی‌خطره) و
قابل‌بررسی (`--dry-run`) هست.

## کامپوننت‌ها و منبعِ هرکدوم

| کامپوننت | پیش‌فرض | ویندوز | لینوکس |
|---|---|---|---|
| `python` | ✅ | `pip install -r requirements.txt` (و با `--with-licensing` هم `requirements-license.txt`)، اختیاری توی `--venv` | همون |
| `teamtalk` | ✅ | از قبل همراه ریپوعه (`core/teamtalk/TeamTalk5.dll`)؛ فقط چک می‌شه | دانلود خودکار نداره (لایسنس/ثبت‌نامِ bearware.dk) -- راهنمای دقیق چاپ می‌شه |
| `ffmpeg` | ✅ | دانلود از [BtbN/FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds) (تگِ `latest`، بیلدِ `win64-gpl-shared`) | اول `apt`/`dnf`؛ نبود/شکست → همون BtbN، بیلدِ `linux64-gpl-shared` |
| `libmpv` | ✅ | دانلود از [shinchiro/mpv-winbuild-cmake](https://github.com/shinchiro/mpv-winbuild-cmake) (آخرین `mpv-dev-x86_64-*.7z`، غیر از نسخه‌ی `-v3-`) -- به یه ابزار `7z`/`7za`/`7zr` روی سیستم نیاز داره؛ نبودش یعنی راهنمای دستی | `apt install libmpv2` (یا `libmpv1`) / `dnf install mpv-libs`؛ دانلودِ جایگزینِ قابل‌اعتمادی برای لینوکس وجود نداره، پس نبودِ apt/dnf یعنی راهنمای دستی |
| `pulseaudio_utils` | ✅ | لازم نیست (بی‌صدا OK) | `apt`/`dnf install pulseaudio-utils` |
| `js_runtime` | ✅ | دانلود `deno` از [denoland/deno](https://github.com/denoland/deno) | همون (بیلدِ لینوکسیِ deno) |
| `xray` | ❌ (اختیاری) | دانلود از [XTLS/Xray-core](https://github.com/XTLS/Xray-core) | همون |

> کامپوننتِ پیش‌فرض یعنی بدون `--components` هم نصب می‌شه. `xray` عمداً
> بیرونه -- فیچری که قراره ازش استفاده کنه هنوز پیاده نشده؛ با
> `--components xray` (تنها یا همراه بقیه) صریح انتخابش کن.

مقصدِ هر فایل نیتیو (کدوم پوشه، چه اسمی روی هر سیستم‌عامل) از
`core/platform_paths.py` (`NATIVE_COMPONENTS`) می‌آد -- همون منبعی که
خودِ ربات موقع اجرا برای پیدا کردنشون می‌خونه (ببین
[`docs/BUILD.md`](BUILD.md#چی-داخل-بیلد-میره) و کامنت‌های
`core/platform_paths.py`). یعنی این اسکریپت هیچ‌وقت فایلی رو جایی
نمی‌ذاره که خودِ ربات دنبالش نگرده.

## گزینه‌ها

| گزینه | کاربرد |
|---|---|
| `--dry-run` | فقط پلن رو چاپ کن؛ هیچ دانلود/نصب/تغییری (حتی ساختن venv) انجام نده. |
| `--components a,b,...` | فقط همین کامپوننت‌ها (لیست کامل بالا). |
| `--with-licensing` | `requirements-license.txt` رو هم نصب کن (پلتفرم فروش/لایسنس). |
| `--venv [PATH]` | وابستگی‌های پایتون رو توی این venv نصب کن (بدون مقدار یعنی `.venv`). بدونش توی همون پایتونی که خودِ `install.py` رو اجرا کردی نصب می‌شه. |

## ایمنی و idempotency

- هر کامپوننت اول با همون تابعی که خودِ ربات موقع اجرا استفاده می‌کنه
  چک می‌شه (`platform_paths.has_ffmpeg()`، `find_native_component`،
  `js_runtime()`، ...)؛ اگه از قبل کار می‌کنه، رد می‌شه (idempotent).
- بعد از هر نصب، دقیقاً همون چک دوباره اجرا می‌شه تا مطمئن بشیم واقعاً
  جواب داد -- نه فقط «فایل کپی شد».
- `--dry-run` هیچ‌وقت به شبکه وصل نمی‌شه و هیچ فایلی نمی‌سازه/عوض
  نمی‌کنه؛ فقط چاپ می‌کنه چی *می‌خواست* انجام بده.
- یه کامپوننتِ خراب کل اسکریپت رو نمی‌ترکونه: خطاش با پیام روشن ثبت
  می‌شه و بقیه‌ی کامپوننت‌ها ادامه پیدا می‌کنن؛ اگه حداقل یکی واقعاً
  شکست خورده باشه (نه فقط نیاز به کار دستی)، کدِ خروج غیرصفره.

## سه‌تا وضعیتِ ممکن برای هر کامپوننت

| وضعیت | یعنی چی |
|---|---|
| از قبل موجود بود | کاری لازم نبود. |
| نصب شد | همین الان دانلود/نصب شد و دوباره چک شد. |
| نیاز به کار دستی | خودکار نمی‌شه (مثلاً SDK لینوکس، یا libmpv ویندوز بدون ابزار 7z) -- راهنمای دقیق همون‌جا چاپ شده. |
| شکست خورد | تلاش شد ولی جواب نداد (مثلاً دانلود قطع شد) -- کدِ خروجِ اسکریپت غیرصفر می‌شه. |

## عیب‌یابی

| نشانه | راه‌حل |
|---|---|
| `libmpv کپی شد ولی هنوز پیدا نمی‌شه` روی ویندوز، بدون ابزار 7z | 7-Zip نصب کن (`7z` روی PATH باشه) و دوباره `python install.py --components libmpv` بزن، یا لینکِ چاپ‌شده رو خودت دستی باز کن. |
| «TeamTalk5 SDK... دانلود خودکار نداره» | طبیعیه -- SDK لایسنس/ثبت‌نامِ bearware.dk می‌خواد. راهنمای دقیق (لینک + مسیر مقصد) توی خروجی چاپ می‌شه. |
| نصب پکیج‌های apt با «Permission denied» | `install.py` خودش با `sudo` صداشون می‌زنه اگه root نباشی؛ اگه سیستم `sudo` نداره (مثلاً بعضی کانتینرها)، اسکریپت رو خودت با root اجرا کن. |
| هنوز هشدارِ «No supported JavaScript runtime» از yt-dlp می‌بینی | `install.py`ی این ریپو فقط *پیدا کردنِ* یه رانتایم رو تضمین می‌کنه (`core.platform_paths.js_runtime()`)؛ وصل‌کردنش به گزینه‌های واقعیِ yt-dlp (`ydl_opts["js_runtimes"]`) یه کارِ جداگانه‌ست. |
| می‌خوام دوباره از صفر امتحان کنم | فایل/پوشه‌ی مربوطه (`bin/`, `core/mpv/`, `core/teamtalk/`) رو دستی پاک کن و دوباره `install.py` رو بزن -- idempotent است، فقط چیزی که واقعاً غایبه رو دوباره می‌گیره. |

## روی لینوکس: چیزهایی که install.py مسئولشون نیست

`deploy/install-linux.sh` هنوز لازمه، چون این کارها اصلاً «نصبِ
وابستگی» نیستن، بلکه تنظیمِ سرویس/سشنِ خودِ سیستمه:

- بستنِ خودِ `python3`/`pip`/`venv` (پیش‌نیازِ اجرای `install.py`).
- سشن صدا (`loginctl enable-linger` + سرویسِ کاربریِ pulseaudio).
- واحدهای systemd (`deploy/ttbot-*.service`).

جزئیاتِ کامل: [`docs/INSTALL-linux.md`](INSTALL-linux.md).
