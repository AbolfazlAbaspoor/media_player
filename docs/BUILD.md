# بیلد فایل اجرایی

```bash
pip install pyinstaller
python build/build.py
```

خروجی داخل `dist/` ساخته می‌شه.

## کراس‌کامپایل ممکن نیست

PyInstaller باینریِ همون سیستمی رو می‌سازه که روش اجرا می‌شه:

| می‌خوای | باید بیلد کنی روی |
|---|---|
| `ttbot.exe` | ویندوز |
| `ttbot` (ELF) | لینوکس |

همین اسکریپت روی هر دو کار می‌کنه و خودش تفاوت‌ها (پسوند، جداکننده‌ی
`--add-data`، اسم کتابخونه‌های نیتیو) رو هندل می‌کنه. یعنی یه بار روی
ویندوز اجراش کن، یه بار روی لینوکس.

## هدف‌ها

```bash
python build/build.py bot        # ttbot           -> bot.py
python build/build.py launcher   # ttbot-launcher  -> launcher.py
python build/build.py license     # ttbot-license   -> license_server.py
python build/build.py manage      # ttbot-manage    -> manage.py
python build/build.py             # همه
```

گزینه‌ها:

```bash
python build/build.py --onefile   # یه فایل تنها (جابه‌جایی راحت، بالا آمدن کندتر)
python build/build.py --clean     # پاک‌کردن dist/ قبل از بیلد
```

## چی داخل بیلد می‌ره

**به‌عنوان داده** (چون در زمان اجرا با `importlib`/`listdir` خونده می‌شن و
PyInstaller نمی‌تونه با آنالیز استاتیک پیداشون کنه) — توی **همه‌ی** هدف‌ها:

- `commands/` — هر دستور ربات
- `core/services/` — یوتیوب، اینستاگرام، تیک‌تاک، ساندکلاد، اسپاتیفای
- `languages/` — فایل‌های ترجمه

**به‌عنوان باینری** (اگه همراه پروژه باشن) — ولی برخلاف داده‌های بالا،
**فقط برای هدفی که واقعاً در زمان اجرا لودشون می‌کنه**. هر هدف توی
`TARGETS[...]["native"]` داخل `build/build.py` صراحتاً می‌گه کدوم‌ها رو
می‌خواد:

| هدف | فایل اجرایی | `native` | چرا |
|---|---|---|---|
| `bot` | `ttbot` | `teamtalk`, `mpv`, `ffmpeg` | `bot.py` مستقیم و توی سطح ماژول `teamtalk.ttbot`، `teamtalk.TeamTalk5` و `mpv.player` رو import می‌کنه (یعنی همون لحظه‌ی بالا اومدن DLL/so لود می‌شه) و از `platform_paths.ffmpeg_location()`/`has_ffmpeg()` برای تبدیل واقعی صدا توسط yt-dlp استفاده می‌کنه. تنها هدفیه که واقعاً صدا پخش/ضبط می‌کنه. |
| `launcher` | `ttbot-launcher` | *(هیچ‌کدوم)* | `launcher.py` ربات رو با `subprocess.Popen` به‌عنوان یه **پروسه‌ی جدا** بالا می‌آره (`bot.py` در حالت توسعه، یا فایل اجرایی `ttbot` کنارش بعد از بیلد) — نه import مستقیم. خودش هیچ‌جا `teamtalk`/`mpv` رو import نمی‌کنه؛ `platform_paths.describe_runtime()`/`missing_runtime_requirements()` فقط یه خط هشدار توی لاگ چاپ می‌کنن و جلوی بالا اومدن ربات‌ها رو نمی‌گیرن. |
| `license` | `ttbot-license` | *(هیچ‌کدوم)* | `license_server.py` هم دقیقاً مثل launcher عمل می‌کنه: ربات‌های مشتری از طریق `licensing/supervisor.py` به‌صورت پروسه‌ی جدا (`subprocess.Popen` روی `bot.py`) بالا می‌آن. خودش import ای از `teamtalk`/`mpv` نداره. (در عمل این هدف اصلاً روی سرور واقعی هم استفاده نمی‌شه: `deploy/ttbot-license.service` مستقیم `python license_server.py` رو اجرا می‌کنه، نه نسخه‌ی فریز‌شده.) |
| `manage` | `ttbot-manage` | *(هیچ‌کدوم)* | زیردستورهای `devices`/`selftest` دستگاه‌های صدا رو از `core/audio_lines.py` می‌خونن، ولی اونجا `from core.mpv.mpv import MPV` و `from core.teamtalk.TeamTalk5 import ...` **تابعی و توی try/except** ایمپورت می‌شن؛ نبودشون یه لیست خالی و پیام روشن («پیدا نشد — libmpv/TeamTalk SDK سر جاشه؟») برمی‌گردونه، نه کرش. `cmd_selftest` هم `player=None, tt=None` می‌ده، یعنی هیچ‌وقت واقعاً دستگاه رو باز نمی‌کنه. دقیقاً همین ~۱۴۰+ مگ باینریِ بی‌مصرف بود که یه بار UPX رو روی این هدف ساعت‌ها هنگ کرده بود. |

روی لینوکس اگه libmpv و ffmpeg از پکیج سیستم نصب باشن، لازم نیست توی
پروژه باشن — بیلد `bot` بدونشون هم ساخته می‌شه و در زمان اجرا از سیستم
استفاده می‌کنه (TeamTalk SDK استثناست: پکیج سیستمی نداره، همیشه باید
همراه پروژه/بیلد باشه).

> `build/package_rental.py` هم همین لیست رو (از `TARGETS["bot"]["native"]`)
> می‌خونه تا قبل از تحویل به مشتری چک کنه این باینری‌ها واقعاً توی بسته
> هستن — چون تنها هدفی که توی بسته‌ی مشتری می‌ره `ttbot` است.

> **پیدا کردنِ این فایل‌ها در زمان اجرا (E16):** اسم‌ها و پوشه‌ی هر
> کدوم از یه رجیستریِ واحد می‌آن (`core/platform_paths.py`,
> `NATIVE_COMPONENTS`) که هم `build.py` بالا و هم خودِ ربات ازش
> می‌خونن. `core.platform_paths.find_native_component()` هر چهار حالتِ
> ممکن رو چک می‌کنه: اجرای مستقیم از سورس، بیلدِ onedir (فایل‌ها زیر
> `_internal/` -- از PyInstaller 6 به بعد، نه کنارِ خودِ `.exe`)، بیلدِ
> onefile (پوشه‌ی موقتِ `sys._MEIPASS`)، و کپیِ دستیِ کاربر کنار فایل
> اجرایی (بالاترین اولویت، تا مشتری بتونه یه DLL جدیدتر رو بدون بیلد
> مجدد جایگزین کنه). قبل از این، چک‌ها فقط کنار خودِ `.exe` رو می‌گشتن
> و روی onedir فایل‌های واقعاً موجود زیر `_internal/` رو «پیدا نشد»
> گزارش می‌کردن.

> **نصبِ خودکارِ این باینری‌ها (E9):** `python install.py` می‌تونه
> ffmpeg/libmpv/SDK تیم‌تاک رو دقیقاً توی همین مسیرها بذاره -- ببین
> [`docs/INSTALL.md`](INSTALL.md).

## چی *بیرون* می‌مونه

پوشه‌ی `data/` — کانفیگ، دیتابیس و دیتای هر نصب. عمداً داخل بیلد نمی‌ره:
کنار فایل اجرایی ساخته می‌شه و با هر آپدیت بیلد پاک نمی‌شه.

`core/paths.py` همین رفتار رو تضمین می‌کنه:

| تابع | در حالت اجرای عادی | بعد از بیلد |
|---|---|---|
| `get_base_dir()` | پوشه‌ی پروژه | پوشه‌ی فایل اجرایی |
| `resource_dir(x)` | پوشه‌ی پروژه | اول کنار exe، بعد داخل باندل |

به‌خاطر همین `resource_dir`، اگه کاربر یه پوشه‌ی `commands/` کنار فایل
اجرایی بذاره، **همون برنده می‌شه** — پس می‌شه بدون بیلد مجدد دستور جدید
اضافه کرد یا یه دستور موجود رو عوض کرد. نسخه‌ی داخل باندل فقط fallback است.

## بیلد نسخه‌ی فروشی (اجاره‌ای، بدون سرور)

اگه می‌خوای مشتری ربات رو روی سیستم خودش اجرا کنه، مسیرِ فعلی لایسنسِ
اجاره‌ای مقابلِ Cloudflare KV است -- کلید عمومی و آدرسِ سرویس از قبل داخلِ
`core/license_key.py` جا داده شده‌ن (با `manage.py deploy-worker`) و نیازی
به فایل/متغیرمحیطیِ جداگانه نیست. جزئیات کامل: [`RENTAL.md`](RENTAL.md).
قبل از تحویل: `python build/package_rental.py --check` و
`python manage.py build-check`.

> نسخه‌ی self-host (توکنِ امضاشده‌ی گرفته‌شده از یه API لایسنسِ خودمون،
> با `license_public.key`/`LICENSE_PUBLIC_KEY` و بخشِ `license` توی
> identity.json) بازنشسته شده.

## حجم بسته

بسته‌ی تحویلی **۱۱۳ مگ** است. اولش ۵۳۱ مگ بود. سه تا کار این راه رو رفت:

| قدم | از | به |
|---|---|---|
| حذف کد مرده (`BOT_EXCLUDES`) | ۵۳۱ | ۳۴۴ |
| ffmpeg full ← essentials | ۳۴۴ | ۳۰۱ |
| فشرده‌سازی UPX | ۳۰۱ | **۱۱۳** |

> عدد **۱۱۳ مگ** بالا فقط مال بسته‌ی مشتری (`ttbot` + `ttbot-launcher` +
> یه `_internal`) است و از قبل هم فقط از هدف `bot` می‌اومد — `package_rental.py`
> همیشه فقط `_internal` خودِ `ttbot` رو کپی می‌کرده (ببین «چی داخل بیلد
> می‌ره» بالا)، پس این عدد با تغییر B10 (هدف‌های native جدا) عوض نشده.
> چیزی که عوض شده حجم/زمانِ **بیلدهای میانی** `dist/ttbot-launcher`،
> `dist/ttbot-license` و `dist/ttbot-manage` است: قبلاً هر سه‌تا هم همون
> سه فایل نیتیوِ خام رو می‌گرفتن که جدول «بزرگ‌ترین قلم باقی‌مونده»
> پایین‌تر اندازه‌شون رو می‌ده (`libmpv-2.dll` ۱۱۰ + `bin/ffmpeg.exe` ۹۸ +
> `TeamTalk5.dll` ۳۰ = **حدود ۲۳۸ مگ خام**)، بدون این‌که هیچ‌کدوم واقعاً
> ازش استفاده کنن. طبق گزارش، دقیقاً همین بار اضافه بود که یه بار UPX رو
> روی `manage` ساعت‌ها هنگ کرده بود؛ الان این سه هدف اصلاً `--add-binary`
> ای برای native ها نمی‌گیرن.

### ۱) چیزهایی که اصلاً اجرا نمی‌شدن

PyInstaller با آنالیز استاتیک برمی‌داشتشون، ولی هیچ‌وقت صدا
زده نمی‌شدن — الان توی `BOT_EXCLUDES` داخل `build/build.py` حذف می‌شن:

| چی | حجم | چرا لازم نیست |
|---|---|---|
| `playwright` | ~۱۰۱ مگ | درایورش یه Node.js کامل (۸۹ مگ) است، ولی *مرورگر* هیچ‌وقت توی بسته نمی‌ره. روی سیستم مشتری این قابلیت در هر حالت fail می‌کرد. |
| `numpy` + openblas | ~۷۵ مگ | فقط `moviepy` لازمش داره، اونم فقط توی مسیرهای **آپلود** instagrapi. ربات فقط لاگین و دانلود می‌کنه. |
| `moviepy` | — | همون دلیل بالا. |
| `tkinter` + tcl/tk | ~۷ مگ | ربات کنسولیه و GUI نداره؛ PyInstaller از روی `PIL.ImageTk` برمی‌داشتش. |

> اگه یه روز خواستی مرورگر رو هم با بسته بفرستی، `playwright` رو از
> `BOT_EXCLUDES` دربیار — وگرنه استخراج لینک از صفحه‌های جاوااسکریپتی
> خاموش می‌مونه (با پیام تمیز، نه کرش).

### فشرده‌سازی با UPX

اگه `build/upx/upx.exe` وجود داشته باشه (یا `UPX_DIR` ست باشه، یا upx توی
PATH باشه)، `build.py` خودش پیداش می‌کنه و بایناری‌ها رو فشرده
می‌کنه. دانلودش از github.com/upx/upx و حجمش نیم مگه.

دستاوردش روی فایل‌های سنگین:

| فایل | قبل | بعد |
|---|---|---|
| `libmpv-2.dll` | ۱۱۰ مگ | ~۳۰ مگ |
| `TeamTalk5.dll` | ۳۰ مگ | ~۱۰ مگ |

دو تا هزینه داره که باید بدونی:

1. **بالا آمدن کمی کندتر.** هر فایل موقع لود توی حافظه باز می‌شه.
   برای رباتی که هفته‌ها بالاست، یکی دو ثانیه یک‌بار مهم نیست.

2. **حساسیت آنتی‌ویروس.** بعضی آنتی‌ویروس‌ها فایلِ UPX‌شده رو
   مشکوک حساب می‌کنن، چون بدافزارها هم باهاش خودشون رو قائم
   می‌کنن. **اگه مشتری گزارش داد ویندوز دفندر فایل رو گرفت، اولین
   کار اینه:**

```bash
python build/build.py bot launcher --clean --no-upx
```

یعنی حجم رو می‌دی تا دردسر نداشته باشی. معامله‌ی خوبیه وقتی
طرف پول داده و فقط می‌خواد ربات بالا بیاد.

> `python311.dll` و DLL های رانتایم ویژوال عمداً فشرده نمی‌شن
> (`UPX_EXCLUDE` توی `build.py`) — لودر ویندوز خودش بازشون می‌کنه و
> با بسته‌ی UPX سر سازگاری ندارن.

### بزرگ‌ترین قلم باقی‌مونده: ffmpeg

سنگین‌ترین قلم‌های بسته (بعد از UPX):

| فایل | خام | توی بسته |
|---|---|---|
| `core/mpv/libmpv-2.dll` | ۱۱۰ مگ | ~۳۱ مگ |
| `bin/ffmpeg.exe` | ۹۸ مگ | ~۲۷ مگ |
| `core/teamtalk/TeamTalk5.dll` | ۳۰ مگ | ~۱۰ مگ |

فایل ffmpeg فعلی **full_build** سایت gyan.dev است: x264، x265، AV1، CUDA،
Vulkan، OpenCL و ده‌ها کدک تصویری. ربات فقط **صدا** کار می‌کنه و از
ffmpeg فقط برای استخراج/تبدیل صدا استفاده می‌کنه.

**این عوض شده:** الان `bin/ffmpeg.exe` نسخه‌ی **essentials** است
(۹۸ مگ خام، ۲۷ مگ بعد از UPX). هیچ قابلیتی از دست نرفت —
lame/opus/vorbis/aac/flac همه توشن (چک شد).

اگه یه روز خواستی دوباره عوضش کنی (مثلاً نسخه‌ی جدیدتر):

1. `ffmpeg-release-essentials.zip` رو از gyan.dev بگیر
2. `bin/ffmpeg.exe` رو باش عوض کن
3. `python build/build.py bot --clean`

> نسخه‌ی full که قبلاً بود x264/x265/AV1/CUDA/Vulkan داشت — همه‌ش برای
> تصویر، درحالی که ربات فقط صدا کار می‌کنه.

## عیب‌یابی بیلد

| نشانه | علت |
|---|---|
| `ModuleNotFoundError` برای یه سرویس | یه import غیرمستقیم که PyInstaller ندید. توی `TARGETS[...]["hidden"]` داخل `build/build.py` اضافه‌ش کن. |
| «دستوری پیدا نشد» بعد از بیلد | پوشه‌ی `commands/` توی بیلد نرفته. خروجی `build.py` رو ببین؛ باید `+ commands` رو چاپ کنه. |
| پیام‌ها به‌جای متن، کلید خام نشون می‌دن | `languages/` توی بیلد نیست. |
| `Cannot find libmpv` روی ماشین مشتری | یا libmpv رو توی بیلد بذار، یا به مشتری بگو `apt install libmpv2` -- یا `python install.py --components libmpv` رو روی همون ماشین بزن (ببین `docs/INSTALL.md`). |
| `ttbot-manage selftest`/`doctor` می‌گه TeamTalk SDK یا libmpv پیدا نشد | طبیعیه: طبق B10 این هدف native ای نداره (جدول بالا). `manage.py`/`ttbot-manage` رو کنار یه نصبِ واقعیِ ربات (که `core/teamtalk/`, `core/mpv/` خودش رو داره) اجرا کن، نه تنها. |
| بسته‌ی مشتری بدون `teamtalk`/`mpv`/`ffmpeg` ساخته شد | `build/package_rental.py --check` قبل از بیلد `bot` با SDK/mpv/ffmpeg کنار پروژه، یا بعد از یه `--clean` ناقص. دوباره `python build/build.py bot` رو با فایل‌های نیتیو سرجاشون بزن. |
